## 1. Цель и критерии успеха

Задача «dry start» (сухой старт): прежде чем строить экраны, отработать на реальном iPhone три основы, которые потом ломают всё.

| # | Аспект | Критерий «сделано» |
|---|---|---|
| 1 | **Запуск** | Приложение с иконки открывается на весь экран. Нет чёрной полосы сверху, нет чёрной полосы снизу. Не нужно «потянуть вниз», чтобы всё починилось. |
| 2 | **Клавиатура** | Открытие и закрытие экранной клавиатуры не ломает вёрстку: поле видно над клавиатурой, под ней нет «края приложения», шапка и страница не «улетают», нет рывка, после закрытия всё на месте. Работает для ВСЕХ видов полей и для самых нижних полей страницы. |
| 3 | **Запуск уведомлений** | Тестовое push-уведомление приходит при закрытом приложении. Отдельный документ: `08-push.md`. |

Критерии проверены владельцем на устройстве; чек-лист для повторной проверки в §9.

| Параметр | Значение |
|---|---|

## 3. Итоговая архитектура

### Слои страницы

```
<html>  height:100%; фон = фон приложения            ← красный при отладке (data-redbg)
 └ <body>  height:100%; min-height:-webkit-fill-available   НЕ fixed, НЕ overflow:hidden
    └ #app  position:relative; height = --app-h (пиксели из JS); overflow:hidden; flex column
       ├ header.header             — шапка (safe-area сверху учтена здесь, один раз)
       ├ main.screen-scroll#list   — ЕДИНСТВЕННЫЙ прокручиваемый блок, flex:1
       ├ nav.tabbar                — position:ABSOLUTE поверх списка, НЕ в потоке
       └ div.rotate                — заглушка для ландшафта
```

### Кто за что отвечает

| Файл | Ответственность |
|---|---|
| `index.html` | Мета-теги (viewport, PWA), критичный фон до загрузки стилей |
| `src/styles.css` | Каркас, шапка, список, панель вкладок, поля. Здесь же живут правила «запаса» под клавиатуру и анимация панели |
| `src/viewport.js` | **Вся логика размеров и клавиатуры** (высота окна, `gap`, запас, возврат, скрытие панели, докрутка) |
| `src/shell.js` | Сборка страницы, вкладки, переходы между экранами, измерение высоты панели |
| `src/debug.js`, `src/eventlog.js` | Лог тапов/фокуса/клавиатуры, красный фон, копирование отчёта |
| `src/screens/*` | Экраны. `lab.js` — «Лаборатория» (стенд для проверки) |

### Принцип в одном абзаце

Мы **не сжимаем окно под клавиатуру и не двигаем содержимое сами**: страницу прокручивает iOS, нативно и плавно, вместе с клавиатурой. Мы лишь **страхуем** три вещи, в которых iOS подводит: (а) под клавиатурой не должно быть края приложения; (б) страницу нельзя двигать пальцем, пока идёт ввод; (в) низкое поле должно оказаться над клавиатурой. И мы **не ждём событий iOS** там, где можно действовать сразу.

## 4. Запуск без чёрных полос

### 4.1. Проблема

Сразу после установки на экране появлялась **чёрная полоса снизу высотой 47 pt** (ровно верхняя безопасная зона). Диагностика на устройстве:

```
screen: 390×844     inner: 390×797     visualViewport: 797 @0     safe-area top/bottom: 47 / 34
```

То есть окно приложения на 47 pt **короче экрана**, а контент при этом рисуется от самого верха (`black-translucent`). Нижние 47 pt лежат вне окна WebView.
Это известный баг WebKit **#301108** (iOS 26): при `viewport-fit=cover` + `black-translucent` система делает окно короче на высоту статус-бара.

### 4.2. Что именно помогло (три компонента вместе)

1. **Структура корня**: `html` и `body` высотой `100%`, `body` с `min-height: -webkit-fill-available`, **без** `position: fixed` и **без** `overflow: hidden`; корень `#app` задан высотой в пикселях.
   С `position: fixed` на `body` (рецепт из ранней версии Библии) нижняя полоса оставалась всегда.
2. **Meta viewport**: `width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover`. Без `interactive-widget` (см. §5.2).
3. **Высота корня из JS**: `--app-h = visualViewport.height + visualViewport.offsetTop + gap`, где
   `gap = max(screen) − innerHeight` (портрет), считается **вычислением**, а не зашитым числом 47. Если iOS окно не урезал, `gap = 0` и формула даёт обычную высоту.
   Источник идеи: старый рабочий проект владельца (там было зашито `+47`; мы сделали вычисляемым, чтобы работало на любой модели).

После этого на устройстве: `inner 390×844`, `gap 0`, `app-h 844`, полос нет ни сверху, ни снизу.

### 4.3. Что нельзя менять без повторной проверки

- Структуру `html/body/#app` (особенно: не добавлять `position:fixed`, `overflow:hidden` на `body`).
- Значение `apple-mobile-web-app-status-bar-style` = `black-translucent` (нужно для полноэкранного вида; `black` убирает баг, но делает статус-бар сплошной чёрной полосой).
- Формулу `--app-h` и функцию `computeGap()` в `viewport.js`.
- Помни: мета-теги `apple-mobile-web-app-*` iOS читает **только при установке**. После их правки иконку нужно удалить и добавить заново.

### 4.4. Диагностика запуска

В Лаборатории (`Ещё → Лаборатория → Отладка → Обновить`) выводятся: `standalone`, `screen`, `inner`, `visualViewport`, `gap`, `app-h`, `safe-area`. Нормальные значения для 390×844: `standalone: true`, `inner 390×844`, `gap 0px`, `app-h 844px`, `safe-area 47px 0px 34px 0px`.
Если при запуске `inner` меньше `screen`, `gap` станет положительным, и `app-h` дотянет корень до низа (в старом проекте это работало).

## 5. Клавиатура

### 5.1. Что делает iOS (факты из логов с устройства)

Измерения с iPhone 390×844. Обозначения: `in` = `innerHeight`, `vv` = `visualViewport.height`, `@N` = `visualViewport.offsetTop`, `y` = `scrollY`.

| Факт | Доказательство из лога |
|---|---|
| Новые размеры приходят с задержкой **~90–110 мс** после фокуса, одной пачкой | `+1 focusin … +104 vv.resize in797 vv441@356 y403` |
| Клавиатура физически выезжает сразу, не дожидаясь событий | см. покадровую запись владельца |
| Для **низких полей** iOS мгновенно прокручивает страницу до максимума (`y` 0 → 403 за ~25 мс) и «центрирует» поле | `f685 → f282, y0 → y403` |
| Для высоких полей прокрутка маленькая или нулевая | `Телефон: y16…27`; `Email: y5` |
| `innerHeight` при открытой клавиатуре «гуляет» (844 → 797 → 633 → 441 → 614 …) | множество строк лога |
| Клавиатура **стеклянная**: через неё и плавающую панель ^ v ✓ виден фон страницы | красный фон: красное под клавиатурой |
| iOS не включает плавающую панель ^ v ✓ в `visualViewport` (зона ~70–80 pt) | `in523 vv441`, разница 82 |
| Поля `date`, `time`, `select` вьюпорт не меняют | в логе нет `клавиатура ОТКРЫЛАСЬ` для них |
| Страницу пальцем при открытой клавиатуре можно уводить к краю документа | «красная линия вырезает контент» |

Следствия: (1) ждать события = рывок, надо готовить всё на фокусе; (2) на `innerHeight` опираться нельзя, высоту клавиатуры считаем как `baseH − vv.height`; (3) под клавиатурой должно быть продолжение страницы, а не её край.

### 5.2. Что мы НЕ делаем

- Не сжимаем окно под клавиатуру (рывок, и документ становится выше окна → iOS прокручивает его до дна).
- Не используем `interactive-widget=resizes-content`: iOS 26 его учитывает, окно сжимается, и получается то же самое.
- Не компенсируем сдвиг панорамы (`translateY(offsetTop)`) на корне: iOS присылает конечное значение сразу, а двигает ~300 мс; шапка «выезжает» или «улетает».
- Не двигаем содержимое сами: прокрутку делает iOS (нативно и плавно).

### 5.3. Алгоритм (по шагам, с таймлайном)

```
t = 0 мс      ТАП по полю
t ≈ 0         focusin (viewport.js):
                · data-edit            → панель вкладок начинает уезжать вниз (transform)
                · запас включается: data-ext, --kbext = 2 × (запомненная высота клавиатуры)
                  [приложение и список удлиняются на запас, нижний отступ списка растёт на ту же величину]
                · запись «открытие» стартует
t ≈ 0…100     клавиатура выезжает; iOS решает, как прокрутить страницу (мгновенно для низких полей)
t ≈ 90…110    visualViewport.resize → sync():
                · kb = baseH − vv.height  (>80 → клавиатура открыта, data-kb=open)
                · запоминаем высоту клавиатуры в localStorage (kbh)
                · запас пересчитывается по реальной высоте
t = 260 мс    revealField(): если поле всё ещё ниже видимой области — плавная докрутка страницы
t = 700 мс    revealField() повторно (страховка)
…             идёт ввод. Страницу пальцем двигать нельзя (touchmove блокируется вне списка)

t = 0         ТАП ВНЕ ПОЛЯ → blur → focusout:
                · schedule() → sync(): data-edit снимается → панель вкладок готова вернуться
                · следующий кадр: scrollTo({top:0, behavior:'smooth'}) — страница плавно возвращается наверх
t ≈ 40…80     visualViewport.resize → kb=closed
t ≈ 250       clearExt(): ждёт, пока scrollY ≤ 1 (до 1.5 с), затем снимает запас; панель выезжает
t = 900 мс    страховка: если страница не вернулась — scrollTo(0,0) + sync()
```

### 5.4. Запас под клавиатуру (самая тонкая часть)

**Зачем.** Если приложение кончается раньше, чем клавиатура, сквозь её стекло виден фон страницы («красная линия», в боевых цветах «чёрная полоса»). Нужно, чтобы под клавиатурой всегда был список.

**Как.** На время ввода (`data-ext`): `#app` высота `+ --kbext`, `.screen-scroll` нижний отступ `+ --kbext`.
Список растёт на ту же величину, что и его отступ, поэтому **предел прокрутки не меняется**: `scrollHeight − clientHeight = const`.

**Почему именно так.**
- Если удлинить только приложение (без отступа), предел прокрутки списка уменьшается, браузер «поджимает» позицию, и список мгновенно съезжает вниз (телепорт). Видно в логе: тап по полю на `y=223`, а в записи фокуса поле уже на `f440`.
- Если удлинить только `body`, iOS доезжает до нового конца документа и красное снова видно.
- **Запас с избытком (2× высоты клавиатуры)**: iOS прокручивает страницу дальше необходимого («центрирует» поле), и ему нужно место.

**Снятие запаса.** Только когда ввода нет И страница вернулась наверх (`scrollY ≤ 1`). Иначе укорочение страницы дёрнет прокрутку.

### 5.5. Запрет прокрутки страницы пальцем

Пока идёт ввод, `touchmove` вне списка отменяется (`preventDefault`, слушатель `passive: false`). Прокручивается только `.screen-scroll` (у него `overscroll-behavior: contain`, он не отдаёт жест странице на краях).
Без этого пользователь мог утянуть страницу к краю документа, и под клавиатурой снова появлялся фон.

### 5.6. Докрутка низкого поля

iOS иногда считает, что поле «достаточно видно» (например, видна его верхняя часть), и не двигает страницу, пока не введён первый символ. Через 260 мс и 700 мс после открытия мы проверяем: нижняя граница поля ниже `vv.offsetTop + vv.height − 28`? Если да, плавно докручиваем (`scrollTo({behavior:'smooth'})`).
Запускается **после** мгновенной прокрутки iOS, а не поверх неё (раньше докрутка мешалась и давала лишние 22 px).

### 5.7. Возврат при закрытии

Плавная прокрутка наверх стартует **сразу** на `focusout`, пока клавиатура ещё уезжает: движение страницы и клавиатуры совпадает. Раньше стояло `scrollTo(0,0)` через 60 мс: мгновенный прыжок на 403 px был самым заметным рывком.

## 6. Панель вкладок

### 6.1. Устройство
`nav.tabbar` лежит **поверх списка** (`position: absolute; bottom: 0`), а не в потоке. У списка есть нижний отступ, равный высоте панели (`--tab-h`, измеряется `ResizeObserver`'ом, потому что зависит от нижней безопасной зоны).

**Почему не в потоке.** Это отклонение от ранних документов (там сказано «панель в потоке flex»), принятое по результатам устройства:
- панель в потоке при вводе оставляла пустой слот 94 pt, который **обрезал список** над клавиатурой («чёрный блок поверх контента»);
- смена высоты списка при появлении/исчезновении панели уменьшала предел прокрутки и **телепортировала** позицию.

### 6.2. Состояния и анимация

| Состояние | Условие | Вид |
|---|---|---|
| Видна | нет ввода | на месте |
| Скрыта | `data-edit` (с момента фокуса) или `data-kb=open` | `transform: translateY(tab-h + 8px)`, ушла за нижний край, клики отключены; **без задержки** |
| Появление | ввод закончился | выезжает обратно с задержкой `--tab-delay` = **0.22 с**, длительность 0.3 с, кривая `cubic-bezier(.2,.9,.25,1)` |

**Зачем задержка.** Без неё появление панели совпадает с уходом плавающей панели клавиатуры (^ v ✓) и создаёт визуальный шум (замечено покадровой записью).
**Зачем «выезд», а не прозрачность.** Сравнили оба варианта на устройстве: владелец выбрал выезд («без прозрачности»). Анимируется только `transform` (правило проекта).

### 6.3. Приклейка к низу экрана
Пока приложение удлинено (`data-ext`), панель стоит на **прежнем** месте на экране: `bottom: var(--kbext)` (сдвиг от нового, дальнего низа) и `translate: 0 var(--sy)` (`--sy` = `scrollY`, обновляется на `scroll`).
Без этого при закрытии клавиатуры панель появлялась посреди экрана и «опускалась» вместе с плавным возвратом страницы.
Приклейка идёт через отдельное CSS-свойство `translate`, а не `transform`: иначе оно анимировалось бы вместе с выездом и панель запаздывала бы за прокруткой.

## 7. Поля без клавиатуры и прочие частные случаи

- **`NO_KEYBOARD_TYPES`** в `viewport.js`: `date`, `time`, `datetime-local`, `month`, `week`, `color`, `checkbox`, `radio`, `range`, `file`, кнопки, `hidden`. Для них клавиатурная логика не запускается (панель вкладок не прячется, запас не включается). `<select>` тоже исключён.
- **`data-nokb`**: атрибут для служебных полей (скрытое поле копирования в буфер). Такие поля не считаются вводом.
- **`contenteditable`** считается вводом (у него есть клавиатура).
- **Аппаратная клавиатура**: клавиатура так и не открывается → через 0.9 с запас снимается.
- **Поворот экрана**: `baseH/baseW` пересчитываются; в ландшафте показывается заглушка «Поверни телефон».
- **Возврат из фона / `pageshow`**: `reset()` пересчитывает размеры и возвращает страницу наверх.
- **Тап вне поля** вызывает `blur()`: на iOS клавиатура сама при тапе по пустому месту не закрывается.
- **Щипок-масштабирование**: `gesturestart` отменяется (мета `user-scalable=no` iOS полностью не соблюдает).
- **Размер шрифта полей ≥ 16 px**: иначе iOS приближает страницу при фокусе.

| 1 | `body {position:fixed; inset:0}` (рецепт из ранней Библии) | Чёрная полоса снизу 47 pt при запуске | Окно короче экрана (WebKit #301108), `fixed` привязан к нему | Не использовать |
| 2 | Высота корня = `screen.height` (без `old`-структуры) | Полоса осталась | Нижние 47 pt вне окна WebView, CSS туда не дотягивается | Работает только вместе со структурой из §4.2 |
| 3 | `100vh`, `100lvh`, `100dvh`, `fill-available` | Полоса осталась | Те же причины | Не использовать для корня |
| 4 | `apple-mobile-web-app-status-bar-style: black` | Полоса исчезла | Окно на весь экран | Не подходит: статус-бар становится сплошным чёрным (ломает дизайн) |
| 5 | «Пинок» вьюпорта (на миг менять `meta viewport`) | Иногда помогал, но ненадёжен | Принудительный пересчёт | Не нужен после перехода на структуру §4.2 |
| 6 | Маскировка полосы цветом (фон `html/body` = цвет панели) | Полоса невидима, но панель стоит выше нативной | Красить нельзя, высота остаётся | Заменено на вычисляемый `gap` + структуру |
| 7 | Сжатие окна под клавиатуру (`#app` = `vv.height`) | Рывок при открытии | Событие приходит с задержкой, экран перестраивается разом | Не сжимать |
| 8 | `interactive-widget=resizes-content` | Окно сжимается, страница уходит до дна | iOS 26 его учитывает | Не указывать |
| 9 | Компенсация сдвига `translateY(offsetTop)` на корне | Шапка «улетает вниз», потом «выезжает» | iOS присылает конечный сдвиг сразу, а двигает ~300 мс | Не компенсировать |
| 10 | `#app { height:100% }` на время ввода | Рывок остался | Всё равно перестройка по событию | Не использовать |
| 11 | Предварительная плавная докрутка поля на фокусе | iOS всё равно сдвигал страницу (поле не успевало приехать к его проверке) | Решение iOS приходит через ~90 мс | Не нужна; iOS справляется сам |
| 12 | Удлинение только `body` | Красное под клавиатурой осталось | iOS доезжает до нового конца документа | Удлинять приложение и список вместе с отступом |
| 13 | Удлинение приложения без нижнего отступа списка | Телепорт позиции списка на ~200 px | Предел прокрутки уменьшился → «поджатие» | Растить отступ на ту же величину |
| 14 | Панель вкладок в потоке | Пустой слот обрезает список над клавиатурой | Слот остаётся после скрытия | Панель `absolute` поверх списка |
| 15 | Панель вкладок появляется после возврата страницы | «Долго появляется», потом вылезает | Ожидание конца прокрутки | Приклеить к низу экрана и показывать сразу |
| 16 | Появление панели сразу при уходе из поля | Совпадает с уходом панели ^ v ✓, визуальный шум | Наложение двух анимаций | Задержка 0.22 с |
| 17 | `scrollTo(0,0)` через 60 мс после `focusout` | Мгновенный прыжок на 403 px, самый заметный рывок | Страница ещё прокручена при закрытии | Плавная прокрутка сразу на `focusout` |
| 18 | `closest('[data-shell]')` в обработчике кликов | Клик по полю перерисовывал страницу → фокус терялся → клавиатура не открывалась | `closest()` дошёл до `<html>`, у него свои `data-*` | Всегда проверять `app.contains(target)` |
| 19 | Поля `date/time/select` считались вводом | Панель пропадала, запас включался впустую | Для них нет клавиатуры | Исключены (`NO_KEYBOARD_TYPES`) |
| 20 | Низкое поле: ждать, пока iOS проведёт к нему | Поле остаётся под клавиатурой до первого символа | iOS счёл его «достаточно видимым» | Докрутка через 0.26 и 0.7 с |

## 9. Чек-лист проверки изменений

Любая правка `src/viewport.js`, каркасных частей `src/styles.css`, `index.html` (мета), структуры `shell.js` проверяется **на телефоне, из иконки на домашнем экране**:

**Запуск**
- [ ] Закрыть приложение полностью (смахнуть) и открыть с иконки: нет чёрных полос сверху и снизу.
- [ ] `Ещё → Лаборатория → Отладка → Обновить`: `inner` = `screen`, `gap: 0px` (или положительный, но без полос).

**Клавиатура (вкладка Лаборатория, поля)**
- [ ] Высокое поле («Текст»): страница не «улетает», шапка на месте.
- [ ] Нижнее поле («Редактируемый блок»): поле над клавиатурой, под клавиатурой список, не красное/чёрное.
- [ ] Очень низкое положение (прокрути список так, чтобы поле было едва видно): клавиатура проводит к нему.
- [ ] Закрыть клавиатуру тапом по пустому месту: страница плавно возвращается, без рывка, панель выезжает чуть позже, без наложения.
- [ ] Включить красный фон (`Отладка → Красный фон`) и повторить для нижних полей: красного нигде не видно, кроме как за краем всего приложения.
- [ ] `date`, `time`, список: панель вкладок не прячется.
- [ ] Страницу пальцем вне списка при открытой клавиатуре не двигается.
- [ ] Светлая тема.

**При любой проблеме**: `Отладка → Копировать лог` и приложить к описанию + скриншот/запись экрана (см. `09-dev-workflow.md`, как читать лог).

## 10. Карта кода и программный интерфейс

### `src/viewport.js`
Экспорт:

| Имя | Что делает |
|---|---|
| `initViewport()` | Подключает слушатели (`focusin/out`, `pointerdown`, `touchmove`, `gesturestart`, `visualViewport`, `scroll`, `pageshow`, `visibilitychange`, `orientationchange`), делает первый `sync()` |
| `onViewportChange(fn)` | Подписка на любое изменение; возвращает функцию отписки |
| `snap()` | Короткая строка состояния для лога |
| `liveLine()` | Строка «окно·видимая@сдвиг» |
| `metrics()` | Подробные метрики для отчёта |
| `recording(kind)` | Запись событий вокруг открытия (`'open'`) или закрытия (`'close'`) клавиатуры |
| `isStandalone()` | Запущено ли с домашнего экрана |

Внутреннее: `sync()` (главный пересчёт), `computeGap()`, `setExt()/clearExt()`, `stickTabbar()`, `revealField()/scheduleReveal()`, `isEditable()`.

### CSS-переменные и атрибуты на `<html>`

| Имя | Кто ставит | Смысл |
|---|---|---|
| `--app-h` | `sync()` | высота `#app` в пикселях |
| `--kbext` | `setExt()` | запас под клавиатуру в пикселях |
| `--sy` | `stickTabbar()` | `scrollY`, приклеивает панель к низу экрана |
| `--tab-h` | `shell.js` (ResizeObserver) | высота панели вкладок |
| `data-kb` = `open`/`closed` | `sync()` | клавиатура подтверждена iOS |
| `data-edit` | `focusin`/`sync()` | идёт ввод (с момента фокуса) |
| `data-ext` | `setExt()/clearExt()` | приложение и список удлинены |
| `data-redbg` | `debug.js` | отладочный красный фон страницы |

### Хранилище
`localStorage`, ключи с префиксом `energoska:`: `kbh` (последняя высота клавиатуры), `redbg`, `screen` (последний открытый экран), `log` (лог отладки).

## 11. Константы

| Значение | Где | Смысл | Как подобрано |
|---|---|---|---|
| `80` pt | `sync()` | порог «клавиатура открыта» | меньше — шум от других изменений высоты |
| `0.8` | `sync()` | не принимать `fullH` меньше 80% базовой | в момент закрытия `vv.height` успевает оказаться маленьким |
| `2 ×` | `setExt` | запас = 2 × высота клавиатуры | iOS центрирует поле и прокручивает дальше нужного |
| `0.48` | `focusin` | оценка высоты клавиатуры при первом фокусе, доля экрана | факт: 403/844 ≈ 0.48 |
| `260`, `700` мс | `scheduleReveal` | моменты докрутки низкого поля | после мгновенной прокрутки iOS (~110 мс) |
| `28` pt | `revealField` | зазор над клавиатурой | визуально |
| `900` мс | `focusin`, `focusout` | страховки (аппаратная клавиатура / плавный возврат не удался) | запас над всей анимацией |
| `300` мс, до 10 попыток × 150 мс | `clearExt` | ожидание возврата страницы | анимация закрытия ≈ 400 мс |
| `0.22 с` | `--tab-delay` | задержка появления панели | чтобы не совпасть с уходом панели ^ v ✓ |
| `0.3 с`, `cubic-bezier(.2,.9,.25,1)` | `.tabbar` | выезд панели | на глаз по покадровой записи |
| `8` pt | `.tabbar` hidden | запас на тень при уходе вниз | визуально |

Любая правка константы требует проверки по чек-листу §9.

## 12. Известные ограничения и открытые вопросы

1. **Рывок при мгновенной прокрутке iOS для самых низких полей** (`y` 0 → 403 за ~25 мс) — это поведение системы. Мы его не отключаем и не сглаживаем, потому что любая попытка (§8, п. 9, 11) делала хуже. Владелец оценил нативное поведение как лучшее.
2. **Светлая тема и статус-бар.** `black-translucent` рисует контент под статус-баром; текст статус-бара iOS выбирает сам. В светлой теме требуется отдельная визуальная проверка.
3. **iPad и ландшафт** не проверялись (приложение рассчитано на портрет, в ландшафте показывается заглушка).
4. **Другие модели iPhone** (с Dynamic Island: safe-area сверху 59 pt; SE: 20 pt) не проверялись. `gap` вычисляется, а не зашит, поэтому ожидаем работоспособность, но это надо подтвердить на устройстве.
5. **Android / Chrome**: клавиатурная логика рассчитана на iOS (`navigator.standalone`), на Android `gap` всегда 0; поведение с клавиатурой — штатное, не проверялось.
6. **Запись событий** (`recording`) ведётся 1.4 с после фокуса; для долгих анимаций можно увеличить в `startRecord`.
7. **Версия iOS** в §2 не зафиксирована — записать при следующей проверке.

## 13. Хронология

Краткая история итераций, чтобы видеть логику развития (подробности в git-истории ветки `claude/epic-pasteur-8mze0j`):

1. Базовый каркас по ранней Библии (`position:fixed`). Полоса снизу 47 pt.
2. Попытки лечить полосу: `screen.height`, `100vh/lvh`, маскировка цветом, смена `status-bar-style`.
3. Старый проект владельца: структура `html/body 100%` + высота корня из JS — полоса исчезла. Принято как основа, формулу сделали вычисляемой.
4. Клавиатура: не открывалась из-за бага в обработчике кликов (`closest` дошёл до `<html>`). Исправлено.
5. Клавиатура: рывки. Серия итераций (сжатие, компенсация, 100% высота). Серия записей событий с устройства выявила порядок событий iOS.
6. Три режима клавиатуры («родной», «фикс», «текущий») для сравнения на ощупь. Выбран «родной» (iOS двигает страницу сам).
7. Красный фон страницы для отладки показал «край документа» под клавиатурой → запас под клавиатуру, плавный возврат, запрет прокрутки страницы пальцем.
8. Панель вкладок: из потока → поверх списка; приклейка к низу экрана; выезд с задержкой.
9. Лаборатория, лог тапов, копирование отчёта в буфер; код переписан начисто с подробными комментариями.
10. Контрольная точка: ветка `checkpoint/kb-best-1` (клавиатура до переписи с режимами).
