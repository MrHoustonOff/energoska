## 1. Принцип работы

- Разработка идёт в облаке (ИИ-агент пишет код и заливает в git). Владелец клонирует репозиторий на компьютер, запускает dev-сервер, открывает адрес на iPhone и проверяет.
- Главная цель на этом этапе — **законченный фронтенд**. Бэкенд откладывается (технологии выбираются позже), данные живут в локальном Mock-Store (`localStorage`).
- Каждая задача — своя ветка; заливка в `main` — после проверки (см. §7).
- Всё, что нельзя проверить в эмуляции (safe-area, клавиатура, push, нагрев, скорость), проверяется **на телефоне из иконки на домашнем экране** и подтверждается логом/скриншотом/записью экрана.

## 2. Запуск на телефоне

### 2.1. Обычный режим (локальная сеть)

```bash
git clone https://github.com/MrHoustonOff/energoska && cd energoska
git checkout <ветка>
npm i
npm run dev
```

В консоли будет строка `Network: http://192.168.x.x:5173/`. Телефон и компьютер должны быть в одной Wi-Fi сети; открыть адрес в Safari.

Ограничения этого режима: страница по **HTTP**, поэтому нет service worker, нет push, нет `navigator.clipboard` (копирование лога работает через запасной путь `execCommand`), нет безопасного контекста.

### 2.2. HTTPS-режим (для push-уведомлений)

```bash
# терминал 1
npm run dev:tunnel
# терминал 2 (cloudflared установить один раз, см. 08-push.md §4)
cloudflared tunnel --url http://localhost:5173
```

Открыть на телефоне адрес `https://….trycloudflare.com`. **Адрес меняется при каждом запуске туннеля**, а значит меняется origin (новая иконка, заново разрешение). Подробно: `08-push.md`.

### 2.3. Обновление кода
После `git pull` Vite подхватывает изменения сам. Если приложение открыто с иконки, закрой его (смахни) и открой заново, чтобы точно загрузилась новая версия.

## 3. Установка и переустановка иконки

Добавление: Safari → «Поделиться» → «На экран Домой». Запускать только с иконки (во вкладке Safari картина другая: другая высота окна, нет push).

Иконку нужно **удалить и добавить заново**, если менялось:
- мета-теги `apple-mobile-web-app-*` в `index.html` (iOS читает их только при установке);
- `manifest.webmanifest` или иконки;
- адрес (например, новый туннель).

Просто «обновить страницу» для этого недостаточно.

## 4. Что проверяется в эмуляции, а что только на железе

Эмуляция: Playwright + Chromium (в облачной среде уже установлен), профиль iPhone 13 Pro.

| Что | Эмуляция | Телефон |
|---|---|---|
| Скрипт не падает, экраны переключаются, кнопки работают | ✅ | ✅ |
| Атрибуты (`data-ext`, `data-kb` …) ставятся и снимаются | ✅ | ✅ |
| Вёрстка, стили, светлая/тёмная тема | ✅ (приблизительно) | ✅ |
| Сохранение данных (`localStorage`) | ✅ | ✅ |
| safe-area, вырез, Home-индикатор | ❌ | ✅ |
| Размеры окна при запуске с иконки (`inner`, `gap`) | ❌ | ✅ |
| Экранная клавиатура и её анимация | ❌ | ✅ |
| Прокрутка страницы iOS при фокусе | ❌ | ✅ |
| Push-уведомления | ❌ (нет push-сервиса; облачная среда блокирует Apple) | ✅ |
| Плавность, нагрев, батарея | ❌ | ✅ |

Правило: **любую правку каркаса, клавиатуры, навигации, анимаций, уведомлений подтверждает телефон**, эмуляция лишь исключает очевидные поломки.

## 5. Инструменты отладки в приложении

Всё собрано в экране `Ещё → Лаборатория` (внизу блок «Отладка») и в модуле `src/debug.js`.

| Инструмент | Где | Для чего |
|---|---|---|
| **Живая строка** | Лаборатория, вверху | `окно·видимая@сдвиг` обновляется на лету: видно, что делает iOS с размерами |
| **Красный фон** | Отладка → «Красный фон» | `html`/`body` красные, приложение своего цвета: красное = то, что Safari считает фоном страницы, т.е. где кончается приложение. В боевых цветах фон страницы равен фону приложения |
| **Лог** | автоматически | Каждый тап, фокус, уход из поля, смена экрана, открытие/закрытие клавиатуры, шаги push. До 400 строк, переживает перезапуск |
| **Запись открытия/закрытия клавиатуры** | автоматически | Подробный таймлайн событий iOS (до 60 строк, 1.4 с) для открытия и для закрытия |
| **Копировать лог** | Отладка | Копирует в буфер полный отчёт (метрики + обе записи + лог). Присылать текстом вместе со скриншотом |
| **Обновить** | Отладка | Показывает отчёт в блоке ниже (если копирование не сработало, текст можно выделить вручную) |
| **Очистить лог** | Отладка | Стирает лог перед новым заходом |

Блоки Лаборатории с атрибутом `data-nolog` в лог не пишутся (чтобы нажатия «Копировать» и т.п. не засоряли его).

### Хороший отчёт о проблеме
1. «Очистить лог».
2. Воспроизвести проблему (по возможности ровно один раз).
3. «Копировать лог» и вставить текстом.
4. Приложить скриншот (при необходимости — запись экрана, лучше покадрово).
5. Указать: какое поле/экран, что ожидалось, что получилось, светлая/тёмная тема.

## 6. Как читать лог и записи

### Строка лога
```
00:14:47.902  фокус fields  input[password] "Пароль"  in844 vv844@0 y0 kb:closed
```
`время` · `событие` (`тап`, `фокус`, `уход`, `клавиатура ОТКРЫЛАСЬ/закрылась`, `экран`, `push`) · `что` (`вид[тип] "название"`) · снимок состояния.

### Снимок состояния
| Обозначение | Что это |
|---|---|
| `in844` | `window.innerHeight` (высота окна страницы). Во время клавиатуры «гуляет» — опираться нельзя |
| `vv441` | `visualViewport.height` (видимая область над клавиатурой) |
| `@356` | `visualViewport.offsetTop` (на сколько видимая область сдвинута относительно окна) |
| `y403` | `window.scrollY` (прокрутка страницы) |
| `kb:open/closed` | подтверждено ли iOS открытие клавиатуры (изменение `vv` больше 80 pt) |

### Строка записи (открытие/закрытие)
```
+104 vv.scroll in797 vv441@356 y403 f282 sc290
```
`+мс от фокуса` · `событие` (`focusin`, `focusout`, `vv.resize`, `vv.scroll`, `kb=open`, `kb=closed`, `reveal` — докрутка) · `in/vv/@/y` как выше · `f282` — нижняя граница поля на экране · `sc290` — прокрутка списка `.screen-scroll`.

### Что искать
- Рывок при открытии ищется по скачку `y` за один шаг (0 → 403).
- «Красная линия»: `vv441` + `y` в максимуме при отсутствии запаса (`запас под клавиатуру: 0`).
- Телепорт списка: `sc` внезапно уменьшилось между `фокус` и первой отметкой записи.
- Опоздавшие события: время `vv.resize` после фокуса (норма 90–110 мс).

## 7. Git: ветки, контрольные точки, заливка

- Основная рабочая ветка агента в облаке: `claude/epic-pasteur-8mze0j`. Для следующих задач — отдельная ветка на задачу.
- Агент **не создаёт pull request без просьбы** и не пушит в чужие ветки.
- Заливка в `main` — после проверки на телефоне и по просьбе владельца (схема: «ветки под таски, заливка в main»).
- Сообщения коммитов — на русском, по сути: `feat:`, `fix:`, `refactor:`, `docs:`, `perf:`, `polish:`, `debug:`.
- **Контрольные точки** — ветки вида `checkpoint/<имя>` на удалённом репозитории (теги из облачной среды отправляются нестабильно, поэтому ветки). Сейчас есть `checkpoint/kb-best-1`: клавиатура до полной переписи с режимами. Вернуться: `git checkout checkpoint/kb-best-1`.
- Секреты в репозиторий не попадают: `.push/` (ключи VAPID и подписки) в `.gitignore`.

## 8. Типовые грабли

| Грабля | Как проявляется | Лечение |
|---|---|---|
| Изменили мета-теги/иконки, а ничего не поменялось | iOS держит старую установку | Удалить иконку и добавить заново |
| Открыли адрес в Safari, а не с иконки | Другая высота окна, нет push, «всё сломалось» | Запускать с иконки |
| `closest('[data-…]')` в обработчике кликов | Срабатывает от `<html>`, у которого свои `data-*` → ложные срабатывания, перерисовка, потеря фокуса | Всегда проверять `app.contains(target)` |
| Переменная `screen` в модуле | Затеняет `window.screen` (`Cannot access 'screen' before initialization`) | Не называть переменные `screen`, `status`, `name`, `top` |
| Менялась высота списка на фокусе | Телепорт позиции прокрутки | Менять высоту и нижний отступ списка на одну и ту же величину (`07-app-shell.md` §5.4) |
| Ждать `visualViewport.resize` для первого действия | Рывок: события приходят через ~100 мс | Действовать на `focusin` |
| `scrollTo(0,0)` после закрытия клавиатуры | Рывок | `scrollTo({behavior:'smooth'})` |
| `navigator.clipboard` на `http` | `undefined` | Запасной путь `execCommand('copy')` (реализован в `eventlog.ts`) |
| Адрес туннеля сменился | Пропали разрешение и подписка | Заново добавить иконку и «Включить» |
| Режим «Фокусировка / Сон» включён | Уведомления не показываются | Выключить на время теста |

## 9. Как работать с ИИ-агентом

- Читать порядок в `AGENTS.md` (§0); решения, заморозки и открытые вопросы — `06-decisions.md`.
- Менять **ровно то, о чём просят**. «Не сломай остальное» действует всегда.
- Если что-то нельзя проверить без телефона, агент обязан так и написать, а не утверждать, что работает.
- Каркас, клавиатура, панель вкладок и push **заморожены** (см. `06-decisions.md`): без прямой просьбы не менять.
- Новые экраны: брать ближайший эталон в `components/INDEX.md`, переносить вёрстку и токены, добавлять состояния (пусто, загрузка, ошибка, нет сети, лимит 2 банки, светлая тема) и состояние «с клавиатурой» для полей.
