## 1. Цель

Доказать на реальном iPhone цепочку «кнопка → уведомление при закрытом приложении» **без бэкенда проекта** и записать, как именно это сделано, чтобы потом не повторять поиски.

Целевой сценарий владельца: открыть приложение, нажать «Тест через 10 с», сразу смахнуть приложение в менеджере окон, через 10 секунд получить уведомление.

В продукте уведомлений четыре типа (`01-product.md`, «Жёсткие правила», п. 7): партнёр выпил энергетик или воду; партнёр закрыл норму воды; партнёр добавил банку, магазин или бренд; фото обработано. Внутри приложения показываются тосты, вне приложения — системный push. Эта схема закрывает технический вопрос «системный push вообще доходит».

## 2. Что умеет iOS и чего нет

Условия для Web Push на iOS (Apple, WWDC22 «Meet Web Push for Safari»; WebKit):

| Условие | Следствие для нас |
|---|---|
| iOS / iPadOS **16.4+** | Выполнено |
| Только для приложения, **добавленного на домашний экран** (`display: standalone`) | Во вкладке Safari push не работает; тест — только из иконки |
| Страница по **HTTPS** (service worker и Push API требуют безопасного контекста; `localhost` — исключение, но телефону он не подходит) | `http://192.168…` не годится → туннель с HTTPS |
| Запрос разрешения **только из жеста пользователя** (нажатие), не при загрузке | Кнопка «Включить»; `requestPermission()` вызывается первым действием в обработчике |
| Нужны **service worker** и **подписка** с ключами **VAPID** | `public/sw.js`, ключи генерирует заглушка |
| **Тихих (silent) push нет**: на каждый push нужно показать уведомление, иначе Safari отзовёт разрешение | Воркер всегда вызывает `showNotification` |
| У Safari **нет запланированных локальных уведомлений** (Notification Triggers не поддерживаются) | Закрытое приложение «само» уведомление не пошлёт → нужен отправитель |
| Push-сервис — **Apple (APNs)**, адрес подписки вида `https://web.push.apple.com/…` | Сообщения идут через Apple |

**Ключевой вывод.** Когда приложение закрыто, его таймеры не работают. Уведомление «через 10 секунд» обязан отправить тот, кто продолжает жить: отдельный процесс. Для теста это процесс на компьютере разработчика.

## 3. Архитектура

```
┌──────────────── iPhone (приложение с иконки, HTTPS-адрес туннеля) ────────────────┐
│ Лаборатория → «Включить»:                                                          │
│   1. Notification.requestPermission()      ← из нажатия                           │
│   2. navigator.serviceWorker.register('/sw.js')                                    │
│   3. GET  /api/push/key                    → публичный ключ VAPID                  │
│   4. pushManager.subscribe({userVisibleOnly:true, applicationServerKey})           │
│   5. POST /api/push/subscribe  (подписка: endpoint + ключи шифрования)             │
│ Лаборатория → «Тест через 10 с»:                                                   │
│   6. POST /api/push/test?delay=10     → ответ сразу (202), дальше приложение можно │
│                                          закрыть                                    │
└───────────────┬──────────────────────────────────────────────────────▲─────────────┘
                │ HTTPS                                                │ 9. push (APNs)
        ┌───────▼───────────┐  туннель  ┌────────────────────────────┐ │   → воркер sw.js
        │  cloudflared      │──────────▶│ Vite dev-сервер (компьютер)│ │   → showNotification
        │  *.trycloudflare  │           │  tools/push-dev-plugin.mjs │ │
        └───────────────────┘           │  · ключи VAPID (.push/)    │ │
                                        │  · хранит подписку         │ │
                                        │  · 7. ждёт 10 секунд       │ │
                                        │  · 8. web-push → Apple ────┼─┘
                                        └────────────────────────────┘
```

### Роли компонентов

| Компонент | Где | Что делает |
|---|---|---|
| Клиент | `src/push.js`, блок в `src/screens/lab.js` | Разрешение, регистрация воркера, подписка, кнопки, статус, пишет шаги в лог |
| Service worker | `public/sw.js` | Принимает `push`, показывает уведомление; по нажатию открывает приложение. **Не кэширует и не перехватывает fetch** |
| Dev-заглушка | `tools/push-dev-plugin.mjs` (подключена в `vite.config.js`) | Ключи VAPID, хранение подписки, отложенная отправка. Живёт только в `npm run dev` |
| Туннель | `cloudflared` (внешняя утилита) | Даёт HTTPS-адрес для телефона |
| Push-сервис | Apple | Доставляет сообщение на устройство |

## 4. Запуск по шагам

Единожды:
1. Установить зависимости: `npm i` (в проекте есть `web-push` в `devDependencies`).
2. Установить туннель `cloudflared` (регистрация не нужна):
   - Windows: `winget install --id Cloudflare.cloudflared`
   - macOS: `brew install cloudflared`
   - Linux/прочее: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/

Каждый раз:
1. **Терминал 1**: `npm run dev:tunnel`  (режим `tunnel` нужен для живой перезагрузки через HTTPS; сервер сам создаст ключи VAPID при первом запуске).
2. **Терминал 2**: `cloudflared tunnel --url http://localhost:5173`. Он напечатает адрес вида `https://что-то.trycloudflare.com`.
3. На телефоне открыть **этот https-адрес** в Safari → «Поделиться» → «На экран Домой».
4. Запустить приложение **с иконки**.
5. `Ещё → Лаборатория`, блок «Уведомления (тест)».

> **Адрес туннеля меняется при каждом запуске.** Это новый origin: новая иконка, заново разрешение и подписка (память приложения привязана к адресу). Для постоянного адреса нужен именованный туннель Cloudflare или выкладка на хостинг (§10).

## 5. Как пользоваться на телефоне

Блок «Уведомления (тест)» в Лаборатории показывает состояние:

```
HTTPS: да
с иконки: да
разрешение: granted
подписка: да
```

1. Нажать **«Включить»** → системный запрос → «Разрешить». Статус: `разрешение: granted`, `подписка: да`. В терминале 1 строка `[push …] подписка сохранена (web.push.apple.com)`.
2. Нажать **«Тест через 10 с»** → внизу `→ отправка через 10 с: закрывай приложение`.
3. Сразу смахнуть приложение в менеджере окон.
4. Через 10 секунд приходит уведомление «Энергоська / Тестовое уведомление (прошло 10 с)». В терминале 1: `[push …] отправлено, ответ Apple/push-сервиса: 201`.
5. Нажатие на уведомление открывает приложение.

Все шаги и ошибки пишутся в общий лог (`Отладка → Копировать лог`).

## 6. Программный интерфейс dev-заглушки

Базовый путь `/api/push`, обработчик — `tools/push-dev-plugin.mjs`. Все ответы JSON, `Cache-Control: no-store`.

| Метод и путь | Тело | Ответ | Описание |
|---|---|---|---|
| `GET /key` | — | `{ publicKey }` | Публичный ключ VAPID (base64url) для `pushManager.subscribe` |
| `POST /subscribe` | подписка `PushSubscription` (JSON: `endpoint`, `keys.p256dh`, `keys.auth`) | `{ ok, subscriptions }` или `400` | Сохраняет подписку; одна на устройство (по `endpoint`), не больше 5 |
| `GET /status` | — | `{ subscriptions: N }` | Сколько подписок известно серверу |
| `POST /test?delay=N` | — | `202 { ok, delay, sendAt }` или `409` | Через `N` секунд (0…120, по умолчанию 10) шлёт тестовое уведомление на все подписки. Отвечает сразу |

Содержимое тестового уведомления (JSON, шифруется библиотекой `web-push`):

```json
{ "title": "Энергоська", "body": "Тестовое уведомление (прошло 10 с)", "tag": "test", "url": "/" }
```

Параметры отправки: `TTL: 60` (сообщение хранится у Apple 60 секунд, если телефон недоступен), `urgency: 'high'` (доставить сразу).
Если Apple отвечает `404` или `410` — подписка мертва (приложение удалено или разрешение отозвано): заглушка её забывает.

## 7. Принятые решения и почему

| Решение | Почему |
|---|---|
| **Отправитель — процесс на компьютере, а не клиент** | Закрытое приложение не может ничего отправить; в Safari нет запланированных локальных уведомлений |
| **Заглушка внутри dev-сервера Vite** (`apply: 'serve'`) | Один процесс, одна команда; в сборку не попадает; это не бэкенд проекта |
| **HTTPS через туннель `cloudflared`** | Нужен безопасный контекст. Самоподписанный сертификат iOS для service worker не принимает. Регистрация не нужна |
| **`allowedHosts: true` и режим `tunnel` в Vite** | Vite 7 отвергает чужие имена хоста; за туннелем HMR должен идти на `wss:443` |
| **Ключи VAPID генерируются один раз и лежат в `.push/`** (в `.gitignore`) | Подписка привязана к публичному ключу; смена ключа ломает подписки. Приватный ключ не должен попасть в репозиторий |
| **Подписки хранятся в `.push/subscriptions.json`** | Переживают перезапуск dev-сервера |
| **VAPID subject = `mailto:energoska-dev@example.com`** | Контакт издателя обязателен по стандарту; для теста подходит условный адрес. Реальный адрес не отправляем во внешний сервис без необходимости |
| **Service worker без `fetch` и кэша** | Кэширующие воркеры «застревают» на старой версии (в режиме с иконки нет кнопки «обновить», см. Библию §8.1). Наш воркер нужен только для push |
| **`skipWaiting()` и `clients.claim()`** | Новая версия воркера вступает в силу сразу |
| **`userVisibleOnly: true`** | Обязательно в Safari: каждый push должен показывать уведомление |
| **Воркер всегда вызывает `showNotification`** | Иначе Safari отзовёт разрешение |
| **`tag` в уведомлении** | Одинаковый `tag` заменяет предыдущее уведомление, а не копит стопку |
| **`requestPermission()` — первое действие в обработчике нажатия, до любых `await`** | Требование жеста пользователя в Safari |
| **Сравнение ключа существующей подписки с ключом сервера** | Если сервер пересоздал ключи, старая подписка отменяется и создаётся новая |
| **Кнопки в Лаборатории, а не в основном интерфейсе** | Это служебный стенд |

## 8. Диагностика: симптом → причина → что делать

Сначала открыть `Ещё → Лаборатория`: блок «Уведомления» показывает состояние; `Отладка → Копировать лог` собирает все шаги.

| Симптом | Причина | Что делать |
|---|---|---|
| `HTTPS: НЕТ` | Страница открыта не по туннельному адресу (по `http://IP`) | Открыть адрес `https://….trycloudflare.com` |
| `с иконки: нет` | Открыто во вкладке Safari | Запускать с домашнего экрана |
| В статусе `⚠ нужен HTTPS…` / `нет Web Push…` | Не выполнено условие §2 | См. текст в статусе |
| Нет запроса разрешения | Запрос разрешения уже был и отклонён, либо вызван не из жеста | iOS: Настройки → Уведомления → приложение → включить; удалить и добавить иконку заново |
| `разрешение: denied` | Пользователь отклонил | Настройки iOS → Уведомления → приложение |
| `разрешение: granted`, `подписка: нет` | Подписка не удалась (смотри строку `→ ОШИБКА` и лог) | Нажать «Включить» ещё раз; проверить, что туннель и dev-сервер работают |
| Ошибка `сервер ответил 404` на `/api/push/key` | Открыто не через dev-сервер (например, сборка) | Запускать `npm run dev:tunnel` |
| «нет подписок: сначала нажми «Включить уведомления»» (409) | Сервер перезапускали без файла подписки или это другой origin | Нажать «Включить» заново |
| В терминале `ОШИБКА отправки: 403 Host not in allowlist …` | Среда запуска блокирует исходящие запросы к Apple (так бывает в облачных песочницах) | Запускать на своём компьютере, не в облачной среде |
| В терминале `ОШИБКА … 410` / `404` | Подписка мертва | Нажать «Включить» ещё раз |
| В терминале `201`, а уведомления нет | Режим фокусировки / «Не беспокоить» / «Сон» скрывает уведомления; выключены уведомления приложения | Выключить фокусировку; Настройки → Уведомления → приложение → разрешить |
| Уведомление пришло при открытом приложении | Так и задумано для теста: iOS показывает баннер и при открытом приложении | — |
| Всё работало, после перезапуска туннеля перестало | Адрес туннеля сменился → новый origin | Заново добавить иконку по новому адресу, «Включить» |
| Всё работало, после перегенерации `.push/vapid.json` перестало | Ключ сервера другой | «Включить» заново (клиент сам отменит старую подписку и подпишется на новый ключ) |
| Живая перезагрузка (HMR) не работает через туннель | Запущено `npm run dev`, а не `npm run dev:tunnel` | Использовать `npm run dev:tunnel` |
| В эмуляции Chromium при «Включить» ошибка `AbortError: Registration failed - permission denied` | В headless Chromium нет push-сервиса | Это не ошибка схемы. Подписку проверять только на iPhone |

## 9. Безопасность

- **`.push/` в `.gitignore`**: там приватный ключ VAPID и подписки. Не коммитить.
- Тестовый эндпоинт `POST /api/push/test` **не защищён**: он только для разработки. Пока запущен туннель, адрес доступен всем, кто его знает (адрес случайный, но всё же). Не оставляйте туннель включённым без необходимости.
- Подписка (`endpoint` + ключи) — это «адрес» для отправки на ваше устройство. Не публиковать её (лог не содержит ключей, но содержит хост push-сервиса).
- Заглушка работает только в `vite serve`; в `vite build` и в `vite preview` её нет.

## 10. Как перейти к настоящему бэкенду

Клиентская часть (`src/push.js`, `public/sw.js`) почти не изменится. Меняется отправитель.

| Что в тесте | Что в продукте |
|---|---|
| Ключи VAPID в `.push/vapid.json` | Ключи в секретах хостинга (переменные окружения). **Один раз сгенерировать и не менять** |
| Подписка одна на dev-сервер | Таблица подписок: `пользователь → устройство(я) → подписка`; удаление при `404/410` |
| `POST /test` с ожиданием 10 секунд | События бэкенда: «партнёр выпил энергетик/воду», «партнёр закрыл норму воды», «партнёр добавил банку/магазин/бренд», «фото обработано» → отправка push |
| Тело `{title, body, tag, url}` | Те же поля; `tag` по типу события (группировка), `url` — экран, куда вести по нажатию |
| Туннель | Постоянный HTTPS-домен |
| Без авторизации | Только авторизованный пользователь; подписку привязывать к его аккаунту |
| Условный контакт VAPID | Реальный контакт проекта (`mailto:` или https) |

Не забыть из продуктовых требований:
- «Попросить разрешение» — двумя шагами по нажатию (`AGENTS.md`, §4) и только в установленном приложении;
- Тосты внутри приложения и push — разные каналы: если приложение открыто и активно, дублировать push не нужно (решение о политике — открытый вопрос продукта);
- Для четырёх типов уведомлений нужен единый формат полезной нагрузки и версионирование.

Хостинг статики: нужен HTTPS-домен; при выкладке в подпапку (например, GitHub Pages `/energoska/`) придётся поправить `base` Vite, `scope`/`start_url` манифеста и путь воркера.

## 11. Результат проверки на устройстве

| Параметр | Значение |
|---|---|
| Дата | 02.10.2026 |
| Устройство | iPhone с экраном 390×844 (см. `07-app-shell.md`, §2) |
| Сценарий | «Включить» → «Тест через 10 с» → смахнуть приложение → ждать |
| Результат | **Получилось**: уведомление пришло при закрытом приложении (подтверждение владельца в чате) |
| Что дописать при следующей проверке | Версия iOS; фактическая задержка доставки; поведение при открытом приложении; поведение с включённым режимом «Фокусировка» |

| `.gitignore` | Исключает `.push/` |
| `.push/` (создаётся сам) | `vapid.json`, `subscriptions.json` |
