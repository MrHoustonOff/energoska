# 11. Контракт API и слой данных

Источник правды: `api/openapi.yaml` (соглашения в его начале). Правила бизнеса: `src/domain/`. Мок: `src/api/mock/`. Контрактные тесты: `src/api/contract/`.

## Как устроено
```
api/openapi.yaml        контракт → npm run api:types → src/api/types.gen.ts (не править руками)
src/domain/             чистые функции правил + constants.ts + scenarios.ts (таблицы «вход → результат»)
src/api/index.ts        интерфейс Api (auth, couple, drinks, ratings, intakes, water, feed); `api` выбирается по VITE_API=mock|http
src/api/mock/           реализация на store.ts (localStorage), задержка и «нет сети» настраиваются
src/api/http/           заглушка (бросает «не реализовано»); настоящая будет вместе с бэкендом
src/api/contract/       suite.ts + suite-data.ts: ОДИН набор тестов для любой реализации Api
```
Экраны используют только `import { api } from '../api'`. Ошибки: `ApiError` (поле `code` из контракта + `network`).

## Соглашения (кратко; полный текст в openapi.yaml)
UUIDv7 создаёт клиент · повтор POST с тем же `id` безопасен (200 вместо 201; другое тело → 409 `id_conflict`) · время ISO UTC, `local_day` считает сервер · оценка целыми десятыми 0..100 · деньги целым в копейках + `BYN`/`RUB` · ошибки `problem+json` · курсорная пагинация · всё ограничено парой (чужое = 404).

## Эндпоинты
| Блок | Метод и путь | Назначение |
|---|---|---|
| auth | GET `/auth/login-available` | логин свободен (+ подсказки) |
| | POST `/auth/register`, `/auth/login`, `/auth/logout` | регистрация, вход (401 `attempts_left`, 429 `retry_after_seconds`), выход |
| | GET/PATCH `/me` | профиль: имя, цвет, норма воды |
| couple | GET/PATCH `/couple` | состояние (`solo`/`incoming`/`paired`), часовой пояс |
| | POST `/couple/join`, `/couple/requests/{id}/accept`, `/decline` | код партнёра → запрос → принять/отклонить |
| drinks | GET/POST `/drinks`, GET `/drinks/{id}` | список страницами, создание, карточка |
| ratings | POST `/ratings`, GET `/drinks/{id}/ratings` | оценка (итог считает сервер), оценки пары |
| intakes | GET/POST `/intakes`, GET `/intakes/day-summary` | записи «выпил», лимит 2/день, сводка дня |
| water | GET/POST `/water` | порции 25..2000 мл, сводка за день |
| | GET/PUT `/water/glasses` | свои стаканы: до 3, 25..1000 мл, замена списка целиком (добавлено в T3) |
| feed | GET `/feed` | лента пары: энергетик (с оценкой автора), порция воды, закрытая норма; курсор (добавлено в T3) |

## Принятые допущения (проверить)
- Лимит 2 банки считается **на человека**, не на пару.
- `over_limit` в пределах лимита и для не-энергетика молча игнорируется (записи из офлайн-очереди приходят не по порядку).
- Принятие запроса в пару переносит банки отправителя в пару принявшего; личные записи (оценки, «выпил», вода) остаются у авторов и видны паре.
- Бренд пока строка в банке (справочник брендов — блок «Справочники»). Разрыв пары, фото, цены, банка дня, push-события в контракт T1 не входят.
- Блокировка входа: 5 неудач → 60 с (`LOGIN_*` в `constants.ts`; точные значения — открытый вопрос №5).

- Лента (T3): только энергетики; запись «сверх лимита» в ленте выглядит как обычная. Новые факты (банка, магазин, бренд) добавят свои блоки.

## Открытые вопросы (одна константа, безопасное умолчание)
`src/domain/constants.ts`: `DAY_BOUNDARY_HOUR = 4` (новый день с 04:00, решено владельцем) и `DEFAULT_TIMEZONE = 'Europe/Minsk'`. Пояс хранится у пары (`PATCH /couple`), час границы пока общий для всех пар.

## Как добавить новый блок
1. Эндпоинты и схемы в `api/openapi.yaml`, `npm run api:types`.
2. Правила (если есть) чистыми функциями в `src/domain/` + строки в `scenarios.ts` + тест.
3. Модуль в интерфейсе `Api`, реализация в `src/api/mock/`, заглушка в `http/`.
4. Сценарии в `src/api/contract/` (они же пройдёт бэкенд). Проверка: `npm run check && npm test && npm run build`.
