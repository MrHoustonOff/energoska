# 12. Демо-данные (мок наполнен из макета)

Зачем: экраны нельзя оценивать на пустом месте. Мок `src/api` при старте приложения сам создаёт пару, каталог банок, оценки, записи и воду **в форме контракта** (`api/openapi.yaml`), так что экран получает данные теми же вызовами `api.*`, какими будет получать от бэкенда.

## Как пользоваться
- Запустил `npm run dev` → вход уже выполнен как **admin / admin** (партнёрша: **dasha / dasha1234**), данные есть.
- **Ещё → Лаборатория → «Демо-данные»**: переключатель состояний. Страница перезагружается, данные пересоздаются.
- Профили (`src/api/mock/demo/profiles.ts`): `empty` (пусто, без пары), `fresh` (утро: сегодня ничего), `one` (обычный день, по умолчанию), `limit` (2 банки), `over` (третья сверх лимита), `long` (180 дней, весь каталог), `solo` (без партнёрши), `incoming` (запрос в пару от Даши).
- Время считается от «сейчас» (граница суток 04:00, пояс пары), поэтому «сегодня» всегда сегодняшнее. Раз в календарный день демо создаётся заново (свои записи за вчера не переживают; это демо). Зерно фиксировано: одно «сейчас» → одни и те же данные.

## Что внутри `src/api/mock/demo/`
| Файл | Что |
|---|---|
| `cast.ts` | Люди (ME, HER) и каталог банок с оценками, цветами, весом «как часто берут». **Править тут**, чтобы поменять наполнение. |
| `profiles.ts` | Сценарии. Добавить сценарий = дописать объект. |
| `generate.ts` | Генератор: события по времени → строки базы. Лимит 2 в день проверяется настоящим `decideIntake` из `src/domain`. |
| `art.ts` | Фото банок: 4 готовых вырезанных из макетов (`public/demo/cans/*.webp`, высоты 96/192/256/384), привязаны к банкам произвольно (плейсхолдеры). Без фото только Coca-Cola; «фото скоро» проверяется созданием новой банки. Плюс аватары. |
| `rng.ts` | Детерминированный генератор случайных чисел. |
| `index.ts` | Подключение: `ensureDemo()`, `switchDemoProfile()`. В шапке: как удалить демо. |
| `demo.test.ts` | Проверки: все профили соответствуют контракту и правилам (формат, лимит, ссылки, детерминированность). |

Панель переключателя: `src/screens/DemoPanel.svelte`.

## Что покрыто и чего ещё нет
В контракте сейчас: пользователи, пара, банки (с полем `photo`), оценки, записи «выпил», вода. Значит демо есть для: Главная (лента, счётчик, вода), Банки (каталог), оценки, пара, вода.
**Нет в контракте, поэтому нет и в демо:** цены и магазины, «Банка дня», уведомления, аватары, статистика (считается на клиенте из записей, данных для неё достаточно: профиль `long`). Когда блоку это понадобится: сначала дописать контракт (`openapi.yaml`, `npm run api:types`), потом поля мока, потом демо (`cast.ts`/`generate.ts`), потом тест.

## Правила для агентов
- Экран получает данные ТОЛЬКО через `api`. Демо-значений в разметке и в компонентах нет.
- Нужно больше данных или новое состояние: расширяй `cast.ts`/`profiles.ts`/`generate.ts`, а не выдумывай в экране. Метка `MOCK-DEMO` на каждом месте, где демо влияет на код.
- Состояния «ошибка / нет сети / загрузка» демо не покрывает: они на стороне `api` (задержка 200 мс, `online()`).

## Как удалить демо
1. Удалить каталог `src/api/mock/demo/`, `public/demo/` и файл `src/screens/DemoPanel.svelte`.
2. `grep -rn MOCK-DEMO src` покажет остальные места (3 строки: `src/api/mock/index.ts`, `src/api/index.ts`, `src/screens/Lab.svelte`). Убрать их; в `src/api/index.ts` оставить `seedAdmin: true`.
3. Поле `photo` в контракте остаётся: оно нужно воркеру фото.
