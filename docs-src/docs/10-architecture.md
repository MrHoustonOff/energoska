# 10. Архитектура и план разработки

> Решения, принятые владельцем 02.10.2026 в беседе с Claude. Статус: **принято**, кроме пунктов «Открыто».
> Контекст: Claude и другие агенты работают в облаке (git push), владелец проверяет через `git pull` на компьютере и iPhone; бэкенд позже.

## 1. Как разрабатывать: контракт первым, вертикальными срезами
Мок сам по себе болит, потому что выдумывает свою форму данных, правила и время. Поэтому:
1. **Контракт API** (OpenAPI) в репозитории (`api/openapi.yaml`): единый источник правды.
2. Фронт ходит на данные через **один слой `api`** с двумя реализациями: мок (`localStorage`) и HTTP. Обе реализации проверяются **одними и теми же тестами**.
3. **Бизнес-правила** (максимум 2 банки в день, граница суток, шаг оценки 0.1, лимит) оформляются таблицей сценариев; по ней проверяются и мок, и бэкенд.
4. Начинать с самого колючего: пользователи и пара, идентификаторы, время, повторная отправка.
5. На блок: контракт → фронт на моке → бэкенд → переключение флагом (`api=mock|http`).
6. **Фронт до конца на моке**, но с контрактом с первого дня. Бэкенд стартует, когда стабильны 2–3 блока (пользователи и пара раньше всех).

## 2. Кто пишет бэкенд
Основной агент (Claude), не слабая модель: он запускает бэкенд и фронт вместе в облаке (там есть Go 1.24 и можно поставить PostgreSQL). Слабую модель использовать для размножения по образцу: сначала эталонный скелет и два эталонных модуля с тестами, остальное по образцу, тесты ловят ошибки. Документация для бэкенда получается из контракта, отдельно не пишется.

## 3. Оптимистичный интерфейс (решение на старте)
Интернет у пары нестабильный (Воронеж, Минск), а кнопка «Энергоснулся» должна реагировать мгновенно. Поэтому: **оптимистичное обновление + очередь отправки** (IndexedDB), идентификаторы генерирует **клиент** (UUIDv7), повторная отправка безопасна (идемпотентность).

## 4. Фронтенд
- **Svelte 5 + TypeScript + Vite.** Причина: компилируется почти в чистый JS, рантайм крошечный, быстрее React. Цель: максимальная скорость на iPhone и Android, минимальная нагрузка.
- Свой CSS по компонентам поверх токенов (`docs-src/tokens/tokens.css`), без огромных файлов; экраны подгружаются по требованию; длинные списки виртуализованы (окно 4 страницы); анимации только `transform`/`opacity`; тяжёлых библиотек нет.
- Файлы до ~300 строк, один модуль на ответственность. Бюджет размера первой загрузки задать в T0.
- **Заморожено и переносится как есть:** `src/viewport.js`, DOM/CSS каркаса, панель вкладок, `push.js`, `sw.js`.

## 5. Бэкенд (позже)
- **Go**, модульный монолит по функциям (пользователи, пара, банки, оценки, вода, статистика, уведомления); внутри слои «обработчик → сервис → репозиторий», бизнес-правила чистыми функциями.
- Стек: стандартная библиотека + `chi`; PostgreSQL; `pgx` + `sqlc` + `goose` (без ORM); `slog`; `argon2id`; сессии в cookie; SSE для событий; `webpush-go`; генерация из OpenAPI (`oapi-codegen`).
- Инвариант: каждый запрос ограничен `couple_id` (изоляция пар), с тестом.
- Данные: оценка целыми десятыми, деньги копейками + валюта (BYN/RUB), время в UTC + часовой пояс пары, идентификаторы от клиента.
- Уведомления: таблица событий (outbox) + воркер отправки (push по `docs/08-push.md`).
- Фото банок: файлы на диске, заранее нарезанные размеры (`XS 96, S 192, M 256, L 384`, WebP).
- Код с подробными комментариями + короткий гайд «как читать этот бэкенд» (владелец изучает Go).

## 6. Хостинг (цель: ноль рублей, постоянный HTTPS)
Адрес должен быть **постоянным до того, как партнёр добавит иконку** (иконка и push привязаны к адресу). Варианты по приоритету:
1. **Tailscale Funnel**: бесплатно, постоянный адрес `имя.tailXXXX.ts.net`, HTTPS, домен не нужен, работает за NAT.
2. **Cloudflare Tunnel с постоянным именем**: нужен домен (копейки в год).
3. **DuckDNS + Caddy** с пробросом портов: нужен белый IP.

Перед выбором — **тест связи** из Воронежа и Минска (Wi‑Fi и мобильная сеть): поведение Cloudflare/Tailscale у российских и белорусских провайдеров из облака проверить нельзя. Для сервера: автообновления, закрытая регистрация (код приглашения), ночной бэкап базы с копией на другой носитель, проверка доступности.

## 7. Процесс с агентами и экономия токенов
- Один блок = одна сессия; первое сообщение короткое; в конце сессия обновляет `STATE.md` и пушит.
- Не читать целиком `app-ux.md` и Библию: `docs-src/docs/app-ux.INDEX.md` указывает диапазоны.
- Тяжёлую модель — на архитектуру и ревью, дешёвую — на механическую работу.
