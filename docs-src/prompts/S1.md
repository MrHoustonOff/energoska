# ЭТАП 1: «Банки, пара, справочники». Все экраны оживить на фикстурах

Прочитай `CLAUDE.md` целиком (протокол, инструменты, цикл на экран) и выполни его для ВСЕХ экранов ниже, по порядку. Внутри этапа не останавливайся; пуш после каждого экрана; ОДИН отчёт в конце. Данные: фикстуры `src/demo-ui/` + `src/<блок>/source.ts` (схема в `CLAUDE.md`, раздел «Данные и демо»). Правил продукта (лимиты, расчёты, сохранение на сервер) НЕ пишем: это этап 3. Нужно, чтобы КАЖДЫЙ элемент каждого кадра эталона был на месте, выглядел как в эталоне и реагировал на нажатие.

## Шаг 0 (один раз, до экранов)
1. Ветка `claude/...` от свежего `main`; `npm i`; `check/test/build` зелёные.
2. Инфраструктура состояний (маленькая, делается один раз, потом только дополняется):
   - `src/demo-ui/states.ts`: реестр `{ screen, state, label }`; функция `forcedState(screen)`.
   - Раздел «Состояния экранов» в `src/screens/Lab.svelte` (отдельный компонент `src/screens/StatesPanel.svelte`): список по экранам, клик открывает экран в состоянии; поддержка ссылки `?s=<экран>:<состояние>&theme=dark|light`. Файл ≤ 300 строк.
3. Общие компоненты в `src/ui/` по эталонам `StickerCan`, `ImageLoading`, `Cover`, `Controls` (прочитай их `README.md` и `preview.html`, `inventory.mjs` для каждого): банка-стикер, плейсхолдеры фото, обложка, контролы (чипы, кнопки-иконки, сегменты, переключатели, поля, фейдер). Остальные экраны используют ТОЛЬКО их. Прежде чем создавать, проверь `src/home/home.css`, `src/auth/*`: совпало с эталоном до пикселя, переиспользуй, нет, заведи общий и перечисли в отчёте отличия.
4. Заменяй заглушки в `src/screens/index.ts` (`ph('cans' ...)` и т.д.) по мере готовности экранов.

## Экраны, в этом порядке
Диапазоны `app-ux.md` читать Read с offset/limit. Кадры = `class="scr"` в эталоне.

**Блок А. Каталог и карточка (вкладка «Банки»), `app-ux.md` 479–587**
1. `ScreenCatalog` (витрина: заголовок, кнопки «Фильтры» с индикатором и «Поиск», чипы, сетка плиток с фото и «Фото скоро»). Чипы переключают и фильтруют показ, плитка ведёт на карточку.
2. `ScreenCatalogLoading` (4 кадра: скелетон, дозагрузка «загружаем ещё», «Нет сети … показаны сохранённые» с «Повторить», поиск «ищем…»). Это состояния каталога и поиска: реализуй их в тех же компонентах и сделай достижимыми.

## Что ещё входит
- Все переходы между этими экранами работают (каталог → карточка → оценка → «сохранено»; новая банка → пикеры → «сохранено»; карточка → бренд/магазин; «Ещё» → пара/справочники). Экраны других этапов (банка дня, цифры, настройки) — заглушки `Placeholder`.
- «Назад» возвращает с сохранением состояния (чип, прокрутка).
- Светлая тема у каждого.

## Критерий приёмки этапа
Таблица в отчёте: 14 экранов × все их кадры, каждый кадр «реализован» и «достижим в Лаборатории»; пары скриншотов «эталон | моё» в `docs-src/reports/S1/`; `check/test/build` зелёные; ни одного демо-значения вне `src/demo-ui`; `grep -rn MOCK-DEMO src` покрывает все места.
