## 1. Контракт (шаг 2 протокола; делай до экрана)
Каталогу нужны оценки «я» и «партнёр» на плитке. Сейчас их можно получить только `api.ratings.list(drinkId)` на каждую банку (N запросов): так нельзя. Дополни контракт:
1. В `api/openapi.yaml` в элементы списка `GET /drinks` добавь два поля `my_score` и `partner_score` (целые 0..100, десятые, `nullable`, описание: итог оценки текущего пользователя / его партнёра по этой банке; `null`, если не оценивал). Поля только в ответе, в `DrinkCreate` их нет.
2. `npm run api:types`, обнови `src/api/types.ts`, мок (`src/api/mock/`), демо-генератор (`src/api/mock/demo/`, пометка `MOCK-DEMO`) и `docs-src/docs/11-api-contract.md`.
3. Тест в `src/api/contract/` (баночка с оценкой обоих, только моей, без оценок).
Если считаешь, что нужно иначе, остановись и спроси.

## 2. Что подставить вместо вшитого (только через `api.drinks.list()`)
- Название: `Drink.name`.
- Оценки: `my_score` (цвет `--me-mark`) и `partner_score` (`--partner-mark`) через `formatTenths` из `src/domain/rating.ts`. Нет оценки: не рисуй число (покажи «—» только если так сказано в `app-ux.md`/README эталона, иначе пусто, и спроси в отчёте).
- Фото: `Drink.photo.urls.h192` (на экране плотностью 2×: `srcset` h192/h384 допустимо), цвет диска `Drink.photo.dominant`. Банка без `photo` (`null`) → плитка бренда (`BrandTile`).
- Плитка бренда: бренд капслоком = `Drink.brand`, строка под чипом = название без префикса бренда (`name` минус `brand` в начале; если префикса нет, целиком `name`). Цвет плитки и цвет текста: чистая функция `brandTileColors(brand)` в `src/domain/catalog.ts` (+ тест): стабильный хэш строки бренда выбирает один из четырёх токенов `--can-burn|gorilla|lit|adrenaline`; текст чёрный на burn/lit, белый на gorilla/adrenaline (как в эталоне). Это решение владельца-архитектора, не меняй.
- Поворот банки ±4°: стабильно от `id` (чётный/нечётный хэш), не `Math.random`.
- Каталог по умолчанию показывает ТОЛЬКО энергетики (`is_energy`), не энергетики только по чипу в фильтрах (экран 3, пока не делаем).

## 3. Чипы
Работает «Все» и те чипы, определение которых есть в `app-ux.md` §5 и считается по данным контракта (`sugar_g_per_100ml`, `my_score`). Фильтрация и сортировка живут в `src/domain/catalog.ts` чистыми функциями с таблицей сценариев в тесте, экран только вызывает. Если определения чипа нет или не хватает данных, чип оставь видимым, а логику не выдумывай: спроси в отчёте. Активный чип один.

## 4. Состояния (скелетон и пустота делай теми же размерами плиток)
1. Обычное. 2. Пусто (нет банок): текст и вид только из `app-ux.md`/README, ничего своего. 3. Загрузка: скелетон из плиток тех же размеров, без анимации кроме `opacity`. (Отдельный экран `ScreenCatalogLoading` будет следующим шагом, здесь минимально корректный скелетон.) 4. Ошибка загрузки и нет сети (`navigator.onLine`): если в `app-ux.md` нет текстов, не выдумывай, спроси. 5. Светлая тема. 6. Банка без фото рядом с банкой с фото в одной сетке.
Тапы: плитка пока ведёт на заглушку карточки (экран 4, не делаем), но кнопки шапки и плитки не должны падать.

## 5. Качество
Как в проходе A, плюс: загрузка списка один раз при открытии, отмена/игнор результата при уходе с экрана (`onDestroy`); список реактивный (`$state`/`$derived`), без `$effect`, где хватает `$derived`; ни одного демо-значения в разметке (`grep -rn MOCK-DEMO src` растёт только в `src/api/mock/demo/` и описанных местах); экран берёт данные только из `api`, в `localStorage` не ходит.
