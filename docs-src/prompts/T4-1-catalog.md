2. **Демо из макета.** В `src/api/mock/demo/` добавь профиль «Каталог из макета» (`MOCK-DEMO`): четыре банки ровно как на эталоне: «Burn Яблоко-киви» (фото, я 8.5, партнёр 7.0), «Gorilla Mango Coconut» (фото, 8.5 / 7.0), «Gorilla Mango Coconut» без фото (бренд Gorilla), «Monster Energy Ultra Paradise» без фото (бренд Monster). Фото берутся из `public/demo/cans`. Плюс в основных профилях есть банки без фото, не-энергетики, сладкие/несладкие, оценённые и неоценённые: чипы должны иметь на чём работать. Тест профиля обязателен (`demo.test.ts`).
3. Подстановка: `Drink.name`; оценки через `formatTenths` (`src/domain/rating.ts`), цвета `--me-mark` / `--partner-mark`; нет оценки: ничего не рисуй, если так не сказано в `app-ux.md`/README; фото `Drink.photo.urls.h192` (`srcset` h192/h384), цвет диска `Drink.photo.dominant`; `photo === null` → плитка бренда: бренд = `Drink.brand`, строка под чипом = `name` без префикса бренда; цвет плитки и текста чистой функцией `brandTileColors(brand)` в `src/domain/catalog.ts` (+ тест): стабильный хэш бренда выбирает один из токенов `--can-burn|gorilla|lit|adrenaline`, текст чёрный на burn/lit и белый на gorilla/adrenaline; наклон банки ±4° стабильно от `id`, без `Math.random`.

## 4. ФУНКЦИОНАЛ: каждый интерактивный элемент макета обязан работать
Не «нарисовано», а реально. Для каждого пункта: действие → результат на экране.
1. **Чипы.** Тап переключает активный (один активный). «Все» — все энергетики; «С сахаром» — `sugar_g_per_100ml > 0`; «Любимые» и «Не пробовал» — по определениям из `app-ux.md` §5 (по `my_score`/`partner_score`). Если определения нет, не выдумывай: спроси в отчёте, чип оставь. Логика фильтра и сортировки в `src/domain/catalog.ts` чистыми функциями + таблица сценариев в тесте. Список перестраивается сразу; при пустом результате — состояние «пусто» из спецификации.
2. **Плитка (оба вида).** Тап ведёт на карточку напитка с id: в `SCREENS` зарегистрируй экран `drink` (заглушка `Placeholder`, `back: 'cans'`, `tab: 'cans'`, показывает название выбранной банки через `api.drinks.get(id)`); «назад» возвращает в каталог С СОХРАНЕНИЕМ активного чипа и позиции прокрутки. Экран-цель настоящий будет в экране 4.
3. **Кнопка «Фильтры».** Тап открывает экран/шторку `filters` (заглушка `Placeholder`, пока нет экрана 3); индикатор числа активных фильтров рисуется только когда число > 0 (состояние в `src/catalog/catalogState.svelte.ts`).
4. **Кнопка «Поиск».** Тап открывает режим поиска по спецификации §5/§10 (если экрана поиска ещё нет — заглушка `search`, но переход работает).
5. **Прокрутка** списка плавная, шапка и панель вкладок остаются как в каркасе.
6. **Состояния** (скелетон/пусто тех же размеров, что плитки): обычное; пусто (нет банок / фильтр без результатов); загрузка (скелетон, анимация только `opacity`); ошибка загрузки; нет сети (`navigator.onLine`); светлая тема. Тексты состояний только из `app-ux.md`/README, нет текста — спроси в отчёте, не выдумывай. Способ вызвать каждое состояние (профиль демо или Лаборатория) назови в отчёте.
7. Данные грузятся один раз при открытии; результат отбрасывается при уходе с экрана (`onDestroy`); реактивность `$state/$derived`, без лишних `$effect`.

## 5. Качество и оптимизация
- Анимации только `transform`/`opacity`. Эталонные плитки статичны: ничего «для красоты».
- Длинный список: у ПЛИТКИ `content-visibility:auto; contain-intrinsic-size:auto <высота>px`; картинки `loading="lazy" decoding="async"` с заданными размерами; наименьший подходящий размер из `urls`; `drop-shadow` стикера как в эталоне, на скролле не пересчитывается.
- Цвета только токены (литералы `#fff/#000` только там, где они в эталоне; перечисли в отчёте). Классы `ct-*`, без глобальных селекторов и `!important`, без `any`, без `localStorage` в экране, ни одного демо-значения в разметке (`grep -rn MOCK-DEMO src`). Файл ≤ 300 строк, одна ответственность: `Catalog.svelte` (экран), `DrinkTile.svelte`, `BrandTile.svelte`, `CatalogHeaderRight.svelte`, `catalogState.svelte.ts`, `catalog.css`; имена без различия только регистром.
