# ScreenRegister — регистрация

Только логин и пароль. Четыре состояния: ввод пароля с подсказкой iOS, ошибки, всё верно, окно Apple «Сохранить пароль?».

## Структура формы (чтобы Apple предложил запомнить)
- Настоящая `<form>`, поля по порядку: логин, пароль, повтор пароля, кнопка `type=submit`.
- Логин: `autocomplete="username"`, без заглавных и автокоррекции.
- Пароль: `type="password"`, `autocomplete="new-password"`. Именно `new-password` включает у iOS подсказку «Надёжный пароль» над клавиатурой.
- Повтор пароля: тоже `autocomplete="new-password"`.
- После успешной отправки форма отправляется как обычная навигация/ответ сервера, не как тихий запрос в фоне — тогда iOS показывает системное окно «Сохранить пароль?». Это окно рисует система, мы его не стилизуем; на экране оно показано пунктирной меткой «Системное окно iOS».
- Подпись под кнопкой заранее готовит человека: «После создания iPhone предложит сохранить пароль — согласитесь».

## Проверки
- Логин: латиница, цифры, `_` и `.`, 3–20 символов. Свободен — зелёная галочка и «Логин свободен» (проверка при уходе из поля). Занят — красная рамка, «Такой логин уже занят» и три варианта чипами (нажатие подставляет).
- Пароль: минимум 8 символов, индикатор надёжности из трёх делений: слабый (красный), средний (жёлтый), надёжный (лайм).
- Повтор: «Пароли не совпадают» показываем после ухода из поля или при отправке; совпали — «Пароли совпадают» с галочкой.
- Кнопка «Создать аккаунт» остаётся белой всегда; при ошибках отправка подсвечивает все неверные поля и прокручивает к первому.
- Пока идёт запрос: спиннер, «Создаём…», поля неактивны.

## Ответ сервера об уже занятом логине
Если логин заняли между проверкой и отправкой — вернуться к полю логина с той же ошибкой.
