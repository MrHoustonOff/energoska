# Design System — "Энергоська"

> Это ЖИВОЙ документ. Каждый новый переиспользуемый визуальный элемент, добавленный в приложение, обязан получить запись здесь — по шаблону из раздела 8. Перед тем как писать любой новый CSS-класс, компонент или цвет — сначала ищи здесь. Если нашёл подходящее — используй как есть. Не нашёл, но элемент универсален — создай и задокументируй. Документ структурирован так, чтобы поиск по ключевым словам (Ctrl+F / grep) сразу находил нужный раздел.

---

## 1. Философия дизайна (не менять без причины)

Продукт — не "ещё один трекер", а личное коллекционирование двух людей, с элементом игры и азарта ("Энергоснулся!"). Визуальный язык должен ощущаться:
- **Материальным** — как будто листаешь полку с банками, а не абстрактную таблицу.
- **Дуальным по умолчанию** — почти каждый показатель принадлежит одному из двух людей или обоим сразу, и это визуально закодировано **всегда одинаково** (см. раздел 3, Identity-цвета).
- **Числа — герои интерфейса.** Оценки, цены, счётчики — не мелкий серый текст сбоку, а главный визуальный акцент экрана, набранный дисплейным шрифтом.
- **Акцент — личный, не рекламный.** Акцентный цвет выбирает пользователь, он приглушённый, не кричащий неон.
- **Движение отвечает касанию.** Никаких анимаций "просто потому что" — анимация появляется как ответ на действие (потянул слайдер, нажал "Выпить", открыл карточку).

Что **запрещено** привносить в дизайн без явного пересмотра этого документа:
- Кремовый фон + контрастный серф + терракотовый акцент (клише "AI-дизайна").
- Единственный кислотно-яркий неоновый акцент на чёрном фоне.
- Одинаковые скруглённые карточки с одной и той же серой тенью на всём подряд.
- ALL-CAPS лейблы, "eyebrow"-подписи над каждым заголовком, точки-разделители вида "A · B · C".

## 2. Типографика

| Роль | Шрифт | Начертания | Где используется |
|---|---|---|---|
| **Display / Numeric** | `Space Grotesk` (или близкий геометричный гротеск с техничным характером) | 500, 700 | Итоговые оценки, цифры на слайдерах, цена, крупные метрики в статистике. Обязательно `font-variant-numeric: tabular-nums` — цифры не должны "прыгать" по ширине при обновлении. |
| **UI / Body** | `Inter` (или `Manrope`) | 400, 500, 600 | Весь остальной текст: лейблы, кнопки, описания, комментарии, навигация. |

### Шкала размеров (CSS-переменные, `tokens/typography.css`)
```css
--font-size-display-xl: 3rem;      /* итоговая оценка на карточке */
--font-size-display-lg: 2rem;      /* крупные метрики статистики */
--font-size-display-md: 1.5rem;    /* цена, вторичные метрики */
--font-size-body-lg: 1.0625rem;    /* основной текст, инпуты (≥16px — см. tech-spec 5.4!) */
--font-size-body-md: 0.9375rem;    /* вторичный текст */
--font-size-body-sm: 0.8125rem;    /* подписи, метаданные, таймстампы */
```
**Правило**: любой `<input>`/`<textarea>`/`<select>` обязан использовать `--font-size-body-lg` (16px) или крупнее — иначе Safari на iOS автоматически зумит страницу при фокусе.

### Правила использования
- Не выделять одно слово в заголовке цветом/курсивом/жирностью — если нужно подчеркнуть число, оно и так уже в Display-шрифте, этого достаточно.
- Никаких ALL-CAPS лейблов. Обычный sentence case везде.
- Максимальная длина строки для описаний/комментариев — ~70 символов на десктопе (на мобильном ограничено шириной экрана естественным образом).

## 3. Цвет

### 3.1 Базовые поверхности (per-theme)

| Переменная | Тёмная тема | Светлая тема | Назначение |
|---|---|---|---|
| `--color-bg` | `#121214` (Ink) | `#F3F4F7` (Fog) | Фон приложения |
| `--color-surface` | `#1C1C20` | `#FFFFFF` | Карточки, модалки |
| `--color-surface-raised` | `#242429` | `#FFFFFF` + тень | Приподнятые элементы (BottomSheet, поповеры) |
| `--color-text` | `#F0F0F2` | `#16171B` | Основной текст |
| `--color-text-muted` | `#9A9AA2` | `#6B6D76` | Вторичный текст, подписи |
| `--color-border` | `#2A2A30` | `#E2E4E9` | Разделители, обводки инпутов |

### 3.2 Identity-цвета (НЕ зависят от темы — см. frontend-architecture.md §2.3)

| Переменная | Значение | Назначение |
|---|---|---|
| `--color-identity-a` (Charge) | `#14C7C2` | Всё, что относится к первому пользователю (Вова) — числа оценок, обводка аватара, заметки на доске, линия на графике |
| `--color-identity-b` (Pulse) | `#FF5C7A` | То же самое для второго пользователя (Даша) |

**Правило использования**: identity-цвета применяются **только** к данным, явно принадлежащим конкретному пользователю. Никогда не использовать Charge/Pulse как декоративный цвет фона, кнопки или иконки, не связанной с авторством данных — это разрушает смысловой код.

### 3.3 Акцентные цвета (выбираемые пользователем, свои для каждой темы)

| Имя | Тёмная тема (hex) | Светлая тема (hex) |
|---|---|---|
| Ash Sage | `#7C9473` | `#5F7857` |
| Dusty Denim | `#5B7FA6` | `#456086` |
| Warm Amber | `#C99A4A` | `#A87B2E` |
| Clay Rose | `#B97B6D` | `#9C5F51` |
| Soft Plum | `#8E6FA0` | `#725582` |

Акцентный цвет (`--color-accent`) используется для: основной CTA-кнопки ("Выпить!", "Энергоснулся"), активного состояния табов/фильтров, фокуса на инпутах, прогресс-баров. **Не используется** для identity-данных (см. 3.2) и не должен визуально сливаться с Charge/Pulse — при добавлении нового варианта в палитру обязательна проверка контраста/различимости против обоих identity-цветов.

### 3.4 Семантические цвета состояний
```css
--color-success: #4FAE7C;  /* сохранено, подтверждено */
--color-danger: #E0616B;   /* архивация, удаление, ошибка */
--color-warning: #D6A44A;  /* предупреждение (например, каскад архивации бренда) */
```

## 4. Отступы, сетка, радиусы

### 4.1 Шкала отступов (8pt-система)
```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 24px;
--space-6: 32px;
--space-7: 48px;
```

### 4.2 Радиусы — по роли, не универсальные
Намеренно **не используем один радиус на всё** (это тот самый признак шаблонного SaaS-дизайна):
```css
--radius-tag: 999px;         /* капсульные теги-фильтры, бейджи */
--radius-button: 14px;       /* кнопки */
--radius-card: 20px;         /* карточки энергетика/бренда/магазина */
--radius-photo-tile: 20px;   /* фото-плитка энергетика — см. 6.1, с "вырезом" под крышечку */
--radius-modal: 24px 24px 0 0; /* нижние шторки (BottomSheet) — скруглены только сверху */
--radius-avatar: 50%;
```

### 4.3 Тень / элевация
Не одна универсальная "мягкая серая тень под всем". Две ступени, обе тонкие и близкие к нейтральному цвету поверхности (не чисто чёрные):
```css
--shadow-sm: 0 1px 2px rgba(0,0,0,0.08);          /* лёгкий подъём (карточка над фоном) */
--shadow-lg: 0 12px 32px rgba(0,0,0,0.24);        /* модалки, BottomSheet */
```
В тёмной теме `--shadow-lg` дополнительно комбинируется с тонкой обводкой `--color-border`, поскольку тени плохо читаются на тёмном фоне.

## 5. Движение (motion)

```css
--motion-fast: 120ms;     /* переключение состояния (тап, тоггл) */
--motion-base: 220ms;     /* появление модалки, разворот карточки */
--motion-slow: 360ms;     /* переход между экранами */
--ease-standard: cubic-bezier(0.4, 0, 0.2, 1);
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1); /* лёгкий "перелёт" — для подтверждающих действий */
```

### Правила
- Анимировать **только** `transform`/`opacity` (см. tech-spec.md §5.6) — никогда `width/height/top/left`.
- Каждое взаимодействие получает **одну** анимацию, не каскад. Пример: кнопка "Выпить!" при нажатии — один `scale(0.96) → scale(1)` c `--ease-spring`, без дополнительных мерцаний/тени/конфетти по умолчанию.
- Единственный "нережиссированный пользователем" момент движения в приложении — открытие модалки/BottomSheet (slide-up + fade, `--motion-base`) и переключение вкладок таб-бара (fade, `--motion-fast`). Никаких fade-in-up анимаций по одной на каждую карточку при скролле списка — это шаблонный паттерн, которого следует избегать.

## 6. Каталог компонентов

> Формат ниже — обязательный шаблон для каждой новой записи (см. раздел 8).

### 6.1 `DrinkPhotoTile` — фото-плитка энергетика
**Где**: `composite/DrinkPhotoTile`
**Описание**: Квадратная плитка с фото энергетика (после удаления фона), с характерной скруглённой "выемкой" в верхнем углу — туда помещается маленькая иконка-крышечка, цвет которой обозначает абсолют (сахар/без сахара: золотая крышечка / серебряная крышечка). Пока фото в обработке — плитка показывает мягкую пульсацию (`opacity` 0.6↔1, `--motion-slow`, зациклено, `prefers-reduced-motion` отключает пульсацию в пользу статичного состояния) и текст "В обработке".
**Токены**: `--radius-photo-tile`, `--color-surface`, `--color-text-muted`.
**Использование**: список энергетиков (уменьшенная версия), карточка энергетика (полноразмерная версия).

### 6.2 `DualValueDisplay` — дуальное значение
**Где**: `composite/DualValueDisplay`
**Описание**: Показывает одно значение в двух ипостасях — крупно (Display-шрифт, `--font-size-display-md` или крупнее) слева в цвете `--color-identity-a`, и мельче (`--font-size-body-lg`) справа в `--color-identity-b`. Используется для итоговой оценки, счётчиков "выпито", любых парных метрик.
**Пропсы (концептуально)**: `primaryValue`, `secondaryValue`, `size` (`sm`/`md`/`lg`), `flipOrder` (на случай, если экран открыт под "партнёра" как основного зрителя).
**Токены**: `--color-identity-a/b`, шрифтовая шкала Display.

### 6.3 `RatingSlider` — слайдер оценки с меткой прошлого значения
**Где**: `composite/RatingSlider`
**Описание**: Нативный `<input type="range" min="0" max="10" step="0.5">`, стилизованный через `::-webkit-slider-thumb`/`::-webkit-slider-runnable-track`. Поверх трека — абсолютно позиционированный элемент-метка (`│`) акцентного цвета на месте предыдущего значения пользователя, с мини-легендой над первым слайдером группы ("│ — ваша прошлая оценка"). Обновление положения "бегунка" — через собственное состояние (controlled input), обновление положения метки прошлого значения — статично при монтировании (не двигается во время драга).
**Токены**: `--color-accent` (метка и заполненная часть трека), `--font-size-display-md` (текущее числовое значение рядом со слайдером, tabular-nums).
**Важно**: см. tech-spec.md §5.5 — производительность и `touch-action: manipulation` обязательны.

### 6.4 `TagChip` — тег/бейдж
**Где**: `primitives/Chip`
**Описание**: Капсульный бейдж (`--radius-tag`) с фоном на основе `accent_color` сущности (тег/бренд/магазин), приглушённым до ~15% opacity на тёмной теме / ~10% на светлой для фона, и полным цветом для текста/обводки. Используется для вкусовых тегов на карточке, фильтров, и в режиме "монохром" — все Chip красятся в единый нейтральный `--color-surface-raised` с текстом `--color-text`.
**Токены**: `--radius-tag`, `--space-2` (внутренний паддинг), `--font-size-body-sm`.

### 6.5 `ColorPicker` — выбор акцентного цвета сущности
**Где**: `primitives/ColorPicker`
**Описание**: Нативный по ощущениям color picker (сетка кружков предустановленных значений + возможность произвольного через системный `<input type="color">` как fallback). Используется для брендов, магазинов, тегов (их `accent_color`), а также в настройках для выбора акцента приложения (там — ограниченный список из 5 вариантов раздела 3.3, без произвольного выбора, чтобы не сломать доступность/контраст).
**Токены**: `--radius-avatar` (кружки-превью цветов), `--space-2` (зазор между кружками).

### 6.6 `PrimaryButton` / `SecondaryButton`
**Где**: `primitives/Button`
**Описание**: `PrimaryButton` — залит `--color-accent`, текст на контрастном к нему цвете (авто-расчёт светлый/тёмный текст по luminance акцента), радиус `--radius-button`, при нажатии — `--ease-spring` scale-анимация (см. раздел 5). `SecondaryButton` — прозрачный фон, обводка `--color-border`, текст `--color-text`.
**Использование**: "Выпить!"/"Энергоснулся" — всегда `PrimaryButton` в самом крупном размере на экране. Второстепенные действия (отмена, "Пропустить") — `SecondaryButton`.

### 6.7 `BottomSheet`
**Где**: `composite/BottomSheet`
**Описание**: Модальная шторка снизу (используется для модалки "Выпить", создания сущностей, инвайта партнёра). `--radius-modal` (скруглена только сверху), появление — slide-up + fade (`--motion-base`, `--ease-standard`), внутренняя структура — flex-shell по паттерну из tech-spec.md §5.4 (шапка шторки `flex: none`, контент `flex: 1 1 auto; overflow-y: auto`, футер с основной кнопкой `flex: none`).
**Правило**: любая форма с полями ввода **обязана** жить внутри `BottomSheet`, а не в кастомной модалке "с нуля" — это гарантирует единообразное поведение с клавиатурой на iOS.

### 6.8 `EmptyState`
**Где**: `composite/EmptyState`
**Описание**: Единый паттерн для пустых экранов (например, "энергетиков пока нет" на списке при первом запуске, "у этого магазина пока нет истории покупок"). Иконка/иллюстрация + один заголовок сентенс-кейсом ("Тут пока пусто") + одна пояснительная строка, описывающая **что делать** ("Добавь первый энергетик кнопкой ниже"), без извинений и общих фраз. Кнопка действия — `PrimaryButton`, если применимо.

### 6.9 `Toast`
**Где**: `primitives/Toast`
**Описание**: Компактное всплывающее подтверждение снизу экрана (над таб-баром, с учётом `env(safe-area-inset-bottom)`), автоскрытие через ~2.5с. Используется для подтверждения сохранения ("Оценка сохранена"), ошибок сети. Текст — в активном залоге, называет произошедшее действие тем же словом, что было на кнопке (см. принцип консистентности терминологии).

## 7. Пустые состояния и ошибки — единый голос

- Пустые экраны — приглашение к действию, не извинение. Плохо: "К сожалению, здесь ничего нет." Хорошо: "Тут пока пусто — добавь первый энергетик."
- Ошибки — конкретны, без "что-то пошло не так" без объяснений. Плохо: "Ошибка." Хорошо: "Не получилось сохранить оценку — проверь соединение и попробуй снова."
- Название действия в кнопке = название результата. Кнопка "Сохранить" → тост "Сохранено". Кнопка "Архивировать бренд" → тост "Бренд архивирован".

## 8. Как расширять этот каталог (обязательная процедура для агента)

При создании нового переиспользуемого компонента/паттерна — добавь запись в раздел 6 по шаблону:

```
### N.N `ИмяКомпонента` — краткое назначение
**Где**: `слой/ИмяКомпонента` (primitives / composite / features/.../components)
**Описание**: что это, из чего состоит, как ведёт себя в ключевых состояниях (пустое/загрузка/ошибка/hover-tap).
**Токены**: какие CSS-переменные из разделов 2–5 использует.
**Использование**: на каких экранах/в каких сценариях применяется.
```

При добавлении нового цвета (акцент, семантический цвет) — обязательно:
1. Указать hex для обеих тем.
2. Проверить контраст с `--color-text`/`--color-bg` (минимум AA для текста).
3. Проверить, что цвет визуально не совпадает и не близок к `--color-identity-a`/`--color-identity-b`.

Если при реализации конкретного экрана возникает необходимость в стиле, которого нет в этом документе, — **не изобретать одноразовый инлайн-стиль молча**. Либо найти ближайший существующий токен/компонент и адаптировать использование под него, либо создать новый переиспользуемый вариант и задокументировать его здесь же, в этом коммите.
