> ## Главная мысль: переносится ВСЁ, что есть в эталоне
> Эталон `docs-src/components/<Экран>/preview.html` описывает экран ЦЕЛИКОМ: несколько кадров (каждый `class="scr"` = отдельное состояние или вариант), десятки классов, анимации, inline-стили. Образец правильной работы уже есть: кнопка «Энергоснулся» на главной (`src/home/ActionButton.svelte`, `monolith.css`, `energyLooks.ts`, `EnergyLab.svelte`): там реализованы ВСЕ формы эталона, все стили, все анимации, и любую форму можно вызвать в Лаборатории. Так же и для КАЖДОГО экрана. Если в `preview.html` есть кадр, цвет, анимация, подпись, вариант плитки — он обязан быть в приложении и достижим. «Основное сделал, остальное потом» = брак.
>
> ## Инструменты (используй их, не считай глазами)
> - `node scripts/inventory.mjs <Экран>` → список ВСЕХ кадров эталона, их тексты, классы, анимации, CSS-правила для переноса. Результат сохрани в `docs-src/reports/<этап>/<Экран>.md` и отмечай `[x]` по мере выполнения. Экран не сдан, пока все пункты `[x]`.

> - Состояние приложения снимай Playwright (390×844) по прямой ссылке на состояние (см. «Состояния экранов»).

> ## Цикл на каждый экран (без остановок внутри этапа)
> 1. **Инвентаризация.** `inventory.mjs` + `frames.mjs`; прочитай `README.md` эталона и нужный диапазон `app-ux.md` (по `app-ux.INDEX.md`, Read с offset/limit; целиком не читать). Спецификация и эталон расходятся: следуй эталону, расхождение запиши в отчёт.
> 2. **Вид.** Перенос ЛОГИЧЕСКИЙ и ПОЛНЫЙ: нужные элементы целиком, значения дословно (теги, классы, размеры, шрифты, анимации); не переносишь рамку телефона, статус-бар, панель вкладок, водный футер, токены, зерно, фон (они есть в `Shell.svelte`, `surface.css`, `Backdrop.svelte`, `src/home/*.css`). Inline-стили эталона переведи в классы с префиксом экрана, значения те же. Вместо значения можно подставить токен только с тем же значением. Не упрощай, не улучшай, не переименовывай.
> 3. **Данные.** Наполнение берётся из фикстуры блока (`src/demo-ui/`), строго то, что нарисовано в эталоне. Экран получает данные из `source.ts`. Фото банок: `public/demo/cans/*`.
> 4. **Оживление.** Каждый элемент, который выглядит нажимаемым или изменяемым, РАБОТАЕТ: чипы, переключатели, сегменты, поля (ввод, очистка), фейдеры (тянутся, значение меняется), шторки и листы (открываются и закрываются), выпадающие списки/пикеры, плитки и строки (ведут на следующий экран), кнопки «назад»/закрыть, анимации и скелетоны. «Без логики» значит: правил продукта нет (лимиты, расчёты, сохранение), есть только отображение, локальное состояние экрана и переходы. Экран, на который перенос ещё не сделан, регистрируется заглушкой `Placeholder`, но переход, id и «назад» работают.
> 5. **Состояния.** Каждый кадр эталона = состояние, которое можно вызвать: Ещё → Лаборатория → «Состояния экранов» (список всех состояний, клик открывает нужный экран в нужном состоянии) и по ссылке `?s=<экран>:<состояние>&theme=dark|light`. Реестр: `src/demo-ui/states.ts` (создаётся на этапе 1, дальше только дополняется).
> 6. **Проверка (на экран).** (а) `check && test && build`; (б) проход по чек-листу инвентаризации; (в) для каждого кадра скриншот приложения рядом с PNG эталона, расхождения исправь, пока не совпадёт; (г) сценарий нажатий в Playwright (что нажал → что увидел); (д) команды из «Самопроверка» ниже. Пары «эталон | моё» в `docs-src/reports/<этап>/`.
> 7. **Коммит** `feat: <экран>` и `git push` СРАЗУ после каждого экрана (владелец смотрит через `git pull`). Обнови прогресс в `STATE.md` (какие экраны готовы), чтобы работу можно продолжить в новой сессии.

> ## Самопроверка (команды выполняй)
> - Регистр имён: `git ls-files | tr 'A-Z' 'a-z' | sort | uniq -d` (пусто). Замороженное: `git diff --stat origin/main -- src/viewport.js index.html` (пусто; `src/styles.css`, `Shell.svelte` только в пределах `STATE.md`).
> - Размер: `find src -name '*.svelte' -o -name '*.ts' -o -name '*.css' | xargs wc -l | sort -rn | head` (файлы ≤ 300 строк, твои правки).
> - Цвета: `grep -rnE "#[0-9a-fA-F]{3,8}" src --include=*.svelte --include=*.css` в твоих файлах: только токены; литералы допустимы лишь те, что есть в эталоне, и перечисли их в отчёте.
> - `grep -rn MOCK-DEMO src` не выросло без причины.
>
> ## Качество кода
> - **Переиспользование:** перед новым компонентом `grep -rn` по `src/`. Повторяется в двух местах → общий в `src/ui/`. Чужие компоненты не правь ради себя.
> - **Оптимизация:** анимируются только `transform`/`opacity`; в длинных списках `content-visibility:auto` + `contain-intrinsic-size` у элемента; картинки `loading="lazy"` и наименьший нужный размер из `Drink.photo.urls`; без `filter`/`box-shadow`, пересчитываемых на скролле; таймеры и подписки снимаются в `onDestroy`; `$derived` вместо лишних `$effect`.
> - **Чистота:** классы с префиксом экрана, без глобальных селекторов и `!important`, без `any`, тексты только из эталона и спецификации, один файл = одна ответственность ≤ 300 строк.
> - **Состояния:** обычное, пусто, загрузка (скелетон тех же размеров), ошибка, нет сети, светлая тема, «с клавиатурой» (где есть поле): ровно те, что нарисованы в эталоне.
>
> **СТОП-правила (не гадай: запиши вопрос в отчёт и продолжи остальное):** нужна правка замороженного; в эталоне есть то, чего нет в спецификации (и наоборот); нужны данные, которых нет в контракте (цены, магазины, бренды: хранить в фикстуре по эталону, в отчёте перечислить, этап 3 добавит в контракт); тест падает не по твоей причине.
> **ЗАПРЕТЫ:** выдуманные тексты и подсказки, тосты (кроме `NotificationToasts` из эталона), новые цвета/шрифты/тени, пропуск кадров и состояний, «потом доделаем», отключение тестов, правки чужих блоков «заодно», обход заморозки, `any` без причины, `localStorage` в экранах, имена файлов, различающиеся только регистром (Windows/macOS владельца).
